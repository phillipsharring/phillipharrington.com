PHP Files, Escaping into PHP, and phpinfo() Phillip Harrington

Web Server Basics ended with settings: where they live, and how they reach your code. Now the code itself. PHP lives in plain text files that end in .php, and a PHP file can hold more than PHP. Most of what makes PHP easy to start with, and easy to make a mess with, comes from that one fact.

What's a PHP File?

A text file the web server hands to PHP instead of sending it. PHP reads it from top to bottom. Anything outside PHP's tags is copied out exactly as it is. Anything inside the tags is code: PHP runs it, and only what the code prints goes out.

The Tags
  • <?php opens PHP, and ?> closes it. Going in and out like that is called escaping into PHP, and you can do it as often as you like.
  • <?= $name ?> is short for <?php echo $name; ?>: print one thing and leave again. It's the tag you'll use most inside HTML.
  • A file that's all PHP opens with <?php on the first line and leaves the closing tag off. That's allowed, and it's the right way: anything after a closing tag, even a stray blank line, gets sent.
    • What's phpinfo()?

    A built-in function that prints a long page about the PHP running it: the version, every setting and where it came from, every extension, the request's headers, and the server's environment variables. It's the fastest way to answer "which PHP is this, and how is it set up?" It's also, for the same reasons, a gift to anyone attacking you.

    Old URLs were full of .php3 and .phtml. Servers were set up to hand files with those extensions to the PHP of the day, so the extension said which version a page was written for. Plain .php won. You'll still find the old ones in server settings that nobody ever cleaned up. How It Works
    1. A request comes in for a file ending in .php.
    2. The server doesn't send the file. It hands it to PHP, the way Document Root described.
    3. PHP reads the file. Text outside the tags goes into the response as it is. Code inside the tags runs, and whatever it prints goes into the response at that spot.
    4. An if or a loop can wrap plain HTML, too, so whole chunks of the page are sent or skipped.
    5. At the end of the file, the response is done. The visitor gets the result, never the code.

    So a .php file is a template and a program at once. That's how PHP started, and it's still handy for small pages. Bigger apps keep the two apart, with the code in files that are all PHP and the HTML in templates that only print. Separating Concerns, much later, is about that.

    Start the server, with a pretend secret in its environment, the way real servers get theirs:

    docker run --rm -it -p 8000:8000 -e API_KEY=pretend-secret -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000

    Open http://localhost:8000, then view the page's source. The HTML is there, with the name and the time filled in, and only one of the two greetings. There's no PHP in it at all: no tags, no $name. The visitor gets the output, never the program.

    Now open http://localhost:8000/info.php and scroll. Your PHP version, every setting, every extension. Then look for the secret:

    curl -s http://localhost:8000/info.php | grep pretend-secret

    There it is, in the Environment section. On a real server, that's your database password and your API keys, on a page anyone can load.

    You don't need a web page for most of this. On the command line, php -v prints the version, php -m lists the extensions, and php -i prints everything phpinfo() does, as plain text:

    docker run --rm php:8.4-cli php -v docker run --rm php:8.4-cli php -m

    In PHP
  • <?php ... ?> for code, <?= ... ?> to print one thing.
  • if (...): ... endif;, foreach (...): ... endforeach;: the colon forms read better than braces when the body is HTML.
  • phpinfo() prints everything, as a web page.
  • php -v, php -m, php -i and php --ini on the command line: version, extensions, everything, and which settings files were loaded.
  • PHP_VERSION is the version, as a string, if your code needs to know.
    •  Gotchas
  • Never leave phpinfo() on a live server. It shows your environment variables, which is where your secrets are, plus your versions, paths and settings: a map for an attacker. Make info.php, read it, delete it. Scanners ask for /info.php and /phpinfo.php all day.
  • Anything outside the tags is output. A blank line or a space before <?php, or after a closing ?>, is sent to the browser. Once anything is sent, PHP can't send headers anymore. Output, next, shows what that breaks.
  • The short <? tag isn't always on. It depends on a setting, short_open_tag, which differs from server to server, and it trips over <?xml. Always write <?php. The <?= tag is always on, so it's fine.
  • A file that isn't .php isn't run. Rename info.php to info.php.bak and the server sends the source as text. Document Root's leftovers gotcha, again.

    • When a setting won't change, run php --ini. It names the php.ini PHP actually loaded, and the extra files it read, and it's often not the one you've been editing. The Docker image loads none at all; it ships two samples, php.ini-development and php.ini-production, in /usr/local/etc/php.
