Output Phillip Harrington

A PHP file's text outside the tags goes out as it is. Everything else that goes out, your code has to print. PHP has several ways to do it: some for the people reading your page, and some for you, while you work out what your code is doing.

What's Output?

Everything PHP sends: the text outside the tags, and whatever the code prints, in the order it happens. On the web, it becomes the body of the response from Request and Response. On the command line, it goes to your terminal. Same code, same output, just a different place for it to land.

For People
  • echo prints one or more strings, separated by commas: echo 'Hi, ', $name;. It's the one you'll use nearly all the time.
  • print is the same idea, for one thing at a time. Most code uses echo.
  • printf() prints a pattern with blanks filled in: printf('%s costs %d cents', $item, $price). %s is a string, %d a whole number.
  • sprintf() does the same, but hands you the string instead of printing it, so you can keep it for later.
    • For You
  • print_r() shows what's in an array, readably.
  • var_dump() shows the type and value of anything: bool(false), string(3) "php". When something is the wrong type, this is how you see it.
  • var_export() writes a value as PHP code you could paste into a file.
    •  The first known "hello, world" program is in Brian Kernighan's 1972 tutorial for B, the language before C. It became famous in 1978, as the first example in The C Programming Language, by Kernighan and Dennis Ritchie. Printing one line has been the first program in nearly every language since. In PHP, it doesn't even need code: a file that says hello, world prints it. How It Works

    On the web, a response is headers first, then the body. So:

    1. Your code runs. While it hasn't printed anything, it can still set headers: header(), http_response_code(), setcookie().
    2. The first byte of output, from an echo or from plain text outside the tags, makes PHP send the headers, right then.
    3. The body follows, as your code prints it.
    4. Any header your code tries to set after that is too late. PHP warns "headers already sent" and ignores it.

    PHP adds one header by itself: Content-Type: text/html; charset=UTF-8, unless you send your own. The charset tells the browser how to read the bytes; Text and UTF-8 has the whole story.

    Try It

    Every way to print, in one file. In a folder, make dump.php:

    docker run --rm -v "$PWD":/app -w /app php:8.4-cli php dump.php

    Look at the line for false: echo printed nothing at all between the brackets. var_dump() shows it as bool(false). When you're checking what a value really is, dump it.

    And too-late.php, which tries to redirect after it's printed:

    docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000

    From a second terminal:

    curl 'http://localhost:8000/?name=Alice' curl --get --data-urlencode 'name=<b>Alice</b>' http://localhost:8000/ curl -i http://localhost:8000/too-late.php Only the new part: Put the data from --data-urlencode in the query string, as a GET, instead of sending it as a POST body.

    The first says hello to Alice. The second sends HTML in the name, and gets back &lt;b&gt;Alice&lt;/b&gt;: escaped, so the browser shows the tags instead of obeying them. Never trust input, and anything that came from outside gets htmlspecialchars() on its way into a page. The third shows no Location header, only the warning: "Cannot modify header information - headers already sent."

    In PHP
  • echo, print, printf(): print for people.
  • sprintf(): build the string, print it later.
  • print_r(), var_dump(), var_export(): print for you.
  • htmlspecialchars($value) on anything from outside that goes into HTML. XSS and Escaping Output, in Security, is why.
  • header('Content-Type: text/plain') when the output isn't HTML, so the browser shows it as it is.
  • headers_sent() tells you whether it's too late for headers.
  • "\n" is a new line (in double quotes); PHP_EOL is the same thing, by name.
    • Gotchas
  • Headers already sent. A redirect, a cookie or a status code after any output is ignored. The warning names the file and line where output started; often it's a blank line before <?php or after a ?>. Set headers first, print second.
  • It works on one server and not another. The sample php.ini files PHP ships turn on output buffering, which holds the first 4 KB of output and hides a late header. The Docker image has no php.ini, so it doesn't. Output Buffering has more. Don't rely on it to fix your order.
  • A new line in HTML is just a space. "\n" breaks lines in the terminal and in page source. In the browser, you need <p> or <br>, or a text/plain content type.
  • Echo hides the type. false and null print as nothing, true prints 1. Debug with var_dump().
  • Escape on the way out, every time. Input that looks harmless in a test is a script tag in an attack. Never trust input.

    • In a browser, print_r() and var_dump() come out as one long line, because HTML ignores the new lines. Wrap them: echo '<pre>'; var_dump($thing); echo '</pre>';. Now it's laid out the way the terminal shows it.
