Classes and Objects Phillip Harrington

So far, data has lived in variables and arrays, and the code that works on it has lived in functions, and nothing kept the two together. Any code anywhere could reach into a cart array and set a price to minus ten dollars. A class puts the data and the code that's allowed to change it in one place, and keeps everything else out.

The line on the stickers on Caching and Naming Things is usually credited to Phil Karlton: "There are only two hard things in computer science: cache invalidation and naming things." Someone, usually said to be Leon Bambrick, finished it properly: "...and off-by-one errors." Hence this sticker. What's a Class?

A blueprint. It describes a kind of thing: what each one knows, and what each one can do. It doesn't do anything by itself, the way a blueprint isn't a house.

Properties and Methods
  • Properties are the variables that belong to each object: a cart's items, its currency.
  • Methods are the functions that belong to the class: add an item, work out the total. Inside a method, $this is the object it was called on.
  • The constructor is a method named __construct. It runs once, when an object is made, to set it up.
    • Public and Private

    Each property and method says who may use it. public: anyone. private: only the class's own methods. protected: the class and classes built on it, which is the next lesson. Make properties private, and the only way to change a cart is through its methods, which can check what they're given.

    What's an Object?

    One thing built from the blueprint. new Cart('USD') makes a cart. Make two, and they're two separate carts: each has its own items, and the same methods.

    Objects and classes come from Simula, a language Ole-Johan Dahl and Kristen Nygaard built at the Norwegian Computing Center in the 1960s, for writing simulations. Modeling a program as a set of things that each keep their own data turned out to be a good way to write programs in general. The two won the Turing Award for it in 2001. PHP got proper objects much later, in PHP 5, in 2004. How It Works
    1. new Cart('USD') makes a fresh object, with every property at its default.
    2. PHP runs the constructor, passing it 'USD'.
    3. new hands back a handle to the object, which you keep in a variable.
    4. $cart->add(...) calls a method on that object. Inside it, $this is that same cart.
    5. When nothing holds a handle to the object anymore, PHP frees it.

    Step three is the surprise. A variable holds a handle, not the object, so $b = $a gives you two handles to one cart. To get a second cart, use clone.

    In PHP
  • class Cart { ... } declares a class. Class names are StudlyCaps, by convention.
  • private array $items = []; declares a property, with a type and a default.
  • public function total(): int declares a method: a function with a visibility.
  • $this->items inside a method; $cart->total() outside.
  • clone $cart copies an object.
  • $cart instanceof Cart asks whether something is an object of that class.
    • Gotchas
  • Assigning an object doesn't copy it. Neither does passing it to a function: the function gets a handle to your object, and can change it.
  • clone is shallow. The copy gets the same values, but if one of them is another object, both copies share that object. Write a __clone() method to copy the insides too.
  • Forgetting $this->. Inside a method, $items is a brand new local variable, not the property. You need $this->items.
  • == and === mean different things here. == asks whether two objects are the same class with equal properties. === asks whether they're the same object.
  • A public property is a promise you can't take back. Once other code sets it directly, you can't add a check without changing all of that code too.

    • Start every property private. Add a method when other code needs something, and make it say what the caller wants, like total(), rather than handing out the raw array. It's easy to open something up later, and very hard to close it again.
