CSV Phillip Harrington

JSON is how programs talk to programs. When the data is for a person, it usually goes into a spreadsheet, and the format for that is CSV. Sooner or later someone asks for an export of the orders, or hands you a file of products to import. Both are easy in PHP, as long as you let PHP do the quoting, and check every row that comes in.

What's CSV?

Comma-separated values: a table as plain text. One line per row, commas between the fields, and usually a first row naming the columns:

sku,name,price_cents TS-01,Plain tee,1500 TS-02,"Tee, with pocket",1800 TS-03,"The ""Classic"" tee",2000

The quoting rules are what make it work:

  • A field with a comma, a quote or a line break in it goes in double quotes.
  • A quote inside a quoted field is written twice: "".
  • Everything is text. Nothing in the file says a column is a number or a date.
    •

    That's most of the standard, RFC 4180, which was written in 2005 to describe what programs were already doing. Many programs still do it a little differently: semicolons instead of commas in countries that write decimals with a comma, different line endings, different character sets.

    Comma-separated data is older than personal computers. IBM's FORTRAN compilers in the early 1970s already read values separated by commas. The name came later than the habit. How It Works

    Reading one:

    1. Open the file, and read the first row as the column names.
    2. Check they're the columns you expect, in the order you expect.
    3. Read the rest one row at a time with fgetcsv(), which handles the quotes and gives you an array of strings.
    4. Check each row: the right number of fields, and each field valid.
    5. Use the good rows, and report the bad ones by line number.

    Writing one is the same in reverse: fputcsv() for each row, which adds whatever quotes a field needs. For a download, write to php://output with the headers from Sending a File.

    A file someone hands you is input, every row of it. It can have missing fields, extra fields, prices that say "free," and text that isn't UTF-8. As Aristotle put it in his lesser-known On Spreadsheets, never trust input, even in a file from a colleague.

    In PHP
  • fgetcsv($file, escape: '') reads one row as an array of strings, or false at the end.
  • fputcsv($file, $fields, escape: '') writes one, quoted as needed.
  • str_getcsv($line, escape: '') parses a single line you already have.
  • escape: '' on all three turns off PHP's own backslash escaping, which isn't part of the standard. PHP 8.4 warns when you leave it out, because the default is going to change.
  • array_combine($header, $fields) turns a row into an array keyed by column name.
  • mb_check_encoding($text, 'UTF-8') before you trust any text from a file.
    • Gotchas
  • Never build a CSV line with implode(',', ...). The first name with a comma in it shifts every column after it. Use fputcsv().
  • Excel and UTF-8 don't always agree. On many setups, Excel opens a plain UTF-8 CSV as if it were an older character set, and "Café" turns into nonsense. Starting the file with a byte order mark, "\xEF\xBB\xBF", tells it otherwise. Then every program reading the file has to skip the mark, like the import does.
  • A cell can be a formula. A field starting with =, +, - or @ is run as a formula when a spreadsheet opens the file. If a visitor's name ends up in your export, they can put a formula in someone else's spreadsheet. That's CSV injection, and the Exporting Data project breaks it and fixes it.
  • Spreadsheets "help" with your data. Open a CSV and save it again, and long numbers can turn into scientific notation, leading zeros vanish from codes like 00742, and things that look like dates become dates. Check a file after a round trip through a spreadsheet.
  • Big files, one row at a time. fgetcsv() reads a row and lets it go, so a million rows use the memory of one. Reading the whole file into an array first uses the memory of all of them.

    • When an import rejects a row, say which line, like the example does. "Line 6: bad price" gets fixed in a minute. "Import failed" gets an email thread. Count the header as line 1, so the numbers match what a spreadsheet shows.
