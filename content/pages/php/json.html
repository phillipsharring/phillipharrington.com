JSON Phillip Harrington

The search endpoint in fetch() and AJAX answered in JSON, and so does nearly every API you'll ever call or build. It's a way to write data as text, so one program can send it to another: PHP to JavaScript, your server to someone else's, a file to your code. PHP's side is two functions. The work is in the flags, and in not believing what arrives.

What's JSON?

JavaScript Object Notation: data written the way JavaScript writes it, with a few strict rules.

{ "id": 42, "size": "large", "gift": true, "note": null, "tags": ["cotton", "blue"] }
  • Objects, in braces: names and values. Names are always strings in double quotes.
  • Arrays, in square brackets: lists.
  • Strings in double quotes (never single), numbers, true and false, and null.
  • No comments, and no comma after the last item.
  • Text in JSON sent between systems is UTF-8, by the standard. From Text and UTF-8: PHP will refuse to encode anything else.
    • PHP and JSON

    JSON's types map onto PHP's almost one to one: an object or an array becomes a PHP array, a string a string, a number an int or a float, and so on. The catch is that PHP uses one kind of array for both lists and key-value pairs. A list, with keys 0, 1, 2 in order, becomes a JSON array. Anything with other keys becomes an object.

    Douglas Crockford, who named and popularized JSON in the early 2000s, says he discovered it rather than invented it: the syntax was already in JavaScript, and people were already using it. His license for his own JSON code added one line to an ordinary open source license: "The Software shall be used for Good, not Evil." Some companies' lawyers refused to approve it. How It Works

    An API that takes JSON gets it like this:

    1. The client sends a POST with Content-Type: application/json and the JSON as the body.
    2. PHP doesn't decode it. $_POST only understands form encoding, so it stays empty. The body waits, as it came, in php://input.
    3. Your code reads it and calls json_decode().
    4. If it isn't JSON, that's a 400. If it is, your code checks the shape: the fields you need are there, of the types you need, in the ranges you allow.
    5. It answers, in JSON, with a status that says what happened.

    Step four is the one people skip. json_decode() succeeding means the text was JSON. It says nothing about whether the JSON is an order. A string where you wanted a number, a list where you wanted an object, a field missing: all valid JSON. Never trust input. Decode it, then check every part of it.

    Try It

    First, both directions on the command line. In a folder, make types.php:

    Run it:

    docker run --rm -v "$PWD":/app -w /app php:8.4-cli php types.php

    Note the line with [] {}: an empty PHP array can't say whether it was a list or not, so it comes out as a list. The bad JSON and the text that isn't UTF-8 both become exceptions, and the last line shows caf\u00e9 next to café: the same text, written two ways.

    Now an endpoint that takes an order as JSON. Make a public folder, and in it, order.php:

    Start the server:

    docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000 -t public

    And from a second terminal, send it a good order, then two bad ones:

    curl -i -H 'Content-Type: application/json' -d '{"size":"large","qty":2}' http://localhost:8000/order.php curl -i -H 'Content-Type: application/json' -d '{"size":"large","qty":"2"}' http://localhost:8000/order.php curl -i -H 'Content-Type: application/json' -d 'size=large' http://localhost:8000/order.php

    Nothing new: -H adds a header, here the one that says "this is JSON," and -d sends the body.

    The first is a 201, with the order. The second is valid JSON with the quantity as a string, "2", not a number, and it's refused with a 422. The third isn't JSON at all: 400.

    In PHP
  • json_encode($value, JSON_THROW_ON_ERROR): PHP to JSON. Without the flag, a failure returns false quietly.
  • json_decode($json, true, 512, JSON_THROW_ON_ERROR): JSON to PHP. true means arrays instead of objects, 512 is how deeply nested it may be, and the flag makes bad JSON a JsonException.
  • file_get_contents('php://input') reads a request body as it arrived.
  • JSON_PRETTY_PRINT for people to read, JSON_UNESCAPED_UNICODE and JSON_UNESCAPED_SLASHES to leave accents and slashes as they are.
  • json_validate($json), since PHP 8.3, checks that a string is JSON without decoding it.
    • Gotchas
  • An empty array is always []. If the other side expects an object, send (object) [], or JSON_FORCE_OBJECT for everything.
  • Removing an item can turn a list into an object. After unset($list[0]), the keys start at 1, so it's no longer a list, and it encodes as {"1": ...}. array_values() renumbers it.
  • Floats aren't for money, in JSON either. 0.1 + 0.2 comes out as 0.30000000000000004. Send cents, as an int.
  • Big numbers lose digits in JavaScript. It can only count exactly to about nine quadrillion. Ids bigger than that, like some from other APIs, should travel as strings.
  • A failed decode looks like null. Without JSON_THROW_ON_ERROR, bad JSON and the JSON null both give you null. Always use the flag.

    • jq pretty-prints JSON and pulls pieces out of it. Pipe any API's answer through it:

    curl -s 'http://localhost:8000/order.php' | docker run --rm -i ghcr.io/jqlang/jq .

    Keep the container's input open, so what comes down the pipe reaches it. No -t, because nobody is typing. The image, from GitHub's registry rather than Docker's, so its name starts with the registry's address. jq's filter: "the whole thing," printed neatly.

    .error instead of . prints just that field. It turns a wall of JSON into something you can read.
