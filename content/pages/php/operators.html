Operators Phillip Harrington

Variables hold values. Operators do things with them: add them, join them, compare them, pick between them. Most work the way you'd guess from school. The comparisons are where PHP's type juggling, from the last lesson, can let the wrong thing through, so they get most of this page.

What's an Operator?

A symbol that takes one or two values and gives back a new one. + takes two numbers and gives back their sum. === takes two values and gives back true or false.

Math
  • + - * /, as usual. / gives a float when it doesn't come out even: 7 / 2 is 3.5.
  • % is the remainder: 7 % 2 is 1. intdiv(7, 2) is the whole-number part, 3.
  • ** is to the power of: 2 ** 10 is 1024.
    •  Joining Strings

    . joins two strings: 'Hello, ' . $name. It's a dot, not a plus. + is always math in PHP, so '1' + '1' is 2, and 'a' + 'b' is a TypeError.

    Assignment and Its Shortcuts

    = puts a value in a variable. $total += 5 is short for $total = $total + 5, and the same goes for -=, *=, /= and .=. $count++ adds one, and $count-- takes one away.

    Comparison

    <, >, <= and >= do what they look like. Then there are two kinds of equal:

  • ===, identical: the same type and the same value. 1 === '1' is false, because one is an int and one is a string. Its opposite is !==.
  • ==, equal after juggling: PHP converts the types first, then compares. 1 == '1' is true. So is '1' == '01', and '10' == '1e1', because two strings that look like numbers are compared as numbers. Its opposite is !=.

    • Use === and !==, always, unless you can say exactly why you want juggling. That's the whole lesson, if you only keep one thing.

    <=>, the spaceship, compares two values and gives back -1, 0 or 1: left smaller, the same, or left bigger. Sorting uses it.

    Logic

    && is and, || is or, and ! is not. $paid && !$shipped is true when it's paid and not shipped yet. PHP stops as soon as it knows the answer, so in $a || $b, $b is never looked at when $a is true.

    Choosing a Value
  • $a ?? $b: $a, unless it's missing or null; then $b. It doesn't warn about a missing key, which makes it right for input: $_GET['page'] ?? '1'. $a ??= $b fills in $a only if it's empty that way.
  • $a ?: $b: $a, unless it counts as false ('', 0, '0', null, false, an empty array); then $b.
  • $test ? $yes : $no, the ternary: one value if the test is true, another if it isn't. $count === 1 ? 'item' : 'items'. One per line; nested ones need parentheses, and are hard to read even with them.
    • BCPL, a language from the 1960s, wrote assignment as := and equality as =. Ken Thompson's B, the language before C, shortened assignment to = and made equality ==. C kept that, and so did nearly everything that borrowed from C, PHP included. Typing = where you meant == has been a classic bug ever since. PHP then added a third, ===, for "and the same type." How It Works

    When PHP meets an expression like $a + $b * 2 > 10:

    1. It decides the order by precedence: * before +, math before comparison, comparison before && and ||, and = nearly last.
    2. It works out each operator's values, juggling types where the operator allows it.
    3. The result of each becomes a value for the next, until one value is left.

    You don't need the precedence table. Use parentheses whenever the order isn't obvious, to you or to the next person: ($a + $b) * 2. They cost nothing and they prevent arguments.

    Check each var_dump() against its comment. The last two are worth a second look: $loose is false, because or binds looser than =, so the assignment happened first.

    Now the reason == matters. code.php checks a one-time code, the kind a site emails you, both ways:

    docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000

    The web server again: -it keeps it in your terminal, so Ctrl+C stops it.

    From a second terminal, guess wrong, then guess 0:

    curl 'http://localhost:8000/code.php?code=123456' curl 'http://localhost:8000/code.php?code=0'

    Both checks refuse 123456. But == lets 0 in. The stored code is 0e and digits, which PHP reads as a number in scientific notation: zero times ten to some power, which is zero. Your '0' is a numeric string too, so == compares them as numbers, and zero equals zero. === compares the strings themselves, and refuses. Codes and tokens made of hex digits look like that now and then, and an attacker only needs one. Never trust input, and never compare it loosely.

    In PHP
  • === and !== for every comparison.
  • in_array($value, $list, true) and array_search($value, $list, true): that last true makes them use ===. Without it, they use ==.
  • hash_equals($expected, $given) for secrets like tokens: strict, and it takes the same time whether the first character matches or not, so timing can't give it away.
  • ?? for reading input that might not be there.
  • intdiv() and % for whole-number division.
    •  Gotchas
  • == on input is a door left open. Two strings that look like numbers are compared as numbers, so '0' equals '0e123', and '1' equals '01'. Compare input with ===, and secrets with hash_equals().
  • PHP 8 changed the rules. Before PHP 8, 0 == 'abc' was true. Now it's false. Old code and old answers online may rely on the old rule.
  • and and or aren't && and ||. They bind looser than =, so $ok = false or true; leaves $ok false. Use the symbols.
  • '0' counts as false. So $input ?: 'default' replaces a real answer of 0. Use ?? when only "missing" should get the default.
  • Strings that look like numbers compare like numbers. '10' < '9' is false, as numbers. Sorting text that might be numeric needs strcmp().

    • The spaceship compares arrays item by item, so sorting by last name, then first, is one line: usort($people, fn($a, $b) => [$a['last'], $a['first']] <=> [$b['last'], $b['first']]);. Swap $a and $b on one side to sort that key backwards.
