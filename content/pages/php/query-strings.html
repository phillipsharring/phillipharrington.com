Query Strings Phillip Harrington

Anatomy of a URL named the part after the ?. It's the simplest way to send a little data with a request: a search, a sort order, a page number, a filter. It's also the most public. It sits in the address bar, where anyone can read it, copy it, bookmark it, or change it.

What's a Query String? /search?q=red+shoes&page=2&tag[]=sale&tag[]=new

Everything after the ?:

  • Pairs of name=value, joined with &.
  • Encoded, so they survive the trip: a space is + or %20, an & inside a value is %26.
  • Repeatable. PHP's convention: a name ending in [], like tag[], collects every value into an array. filter[color]=red makes an array with keys.
    • Ever seen utm_source= on the end of a link? UTM stands for Urchin Tracking Module. Urchin was a web analytics company, bought by Google in 2005, whose software became Google Analytics. Its name has been hitchhiking on links ever since, long after the company it named stopped existing. How It Works
    1. Something builds the URL: a link, a search form, JavaScript, or a person typing.
    2. The browser sends it as part of the request line: GET /search?q=red+shoes.
    3. PHP splits it up, decodes it, builds any arrays, and hands it to you as $_GET.

    Use a query string for things that describe what to show: what to search for, how to sort, which page. Those are safe to repeat, worth bookmarking, and worth sharing. Don't use one for anything that changes data (that's a POST, from Request and Response), or for anything secret.

    And notice step one: "a person typing." As I've said before, never trust input. Whatever you expect in $_GET, someone can send something else. A missing value, an empty one, a word where you wanted a number, a negative page number, an array where you wanted a string. Your code decides what to accept.

    The + became a space, and tag became an array. Now send it garbage, the way someone eventually will, usually at 3 a.m.:

    http://localhost:8000/?q[]=x&page=banana&tag=solo

    Look at the raw $_GET at the bottom: q arrived as an array and page as a word. The code at the top shrugged both off: an empty search, page 1. Try page=-5 too, or try to make the Page line say anything but a positive whole number. The PHP script won't let you. And try a search for <script>alert(1)</script>: it comes back as plain text, because the page says it's text/plain. On an HTML page you'd have to escape it yourself. That's the XSS lesson, in Security.

    In PHP
  • $_GET is the query string, decoded, with arrays already built. Every value in it is input. Check it.
  • filter_var() checks and converts in one step: FILTER_VALIDATE_INT with a min_range is a page number, FILTER_VALIDATE_EMAIL an email address. It returns false when the value doesn't qualify.
  • http_build_query() builds a query string from an array, encoding everything: ['q' => 'red shoes', 'page' => 2] becomes q=red+shoes&page=2. Use it for every link you build; don't glue strings together.
    • Gotchas
  • A string can arrive as an array. Add [] to any name, and PHP makes it an array. Code that passes $_GET['q'] straight to a function expecting a string then crashes. Check the type before you use it.
  • Query strings are public. They're written to server logs, saved in browser history, and can be passed to the next site you visit. Never put a password or a secret in one. (A private window keeps your own searches out of your history, but the site's server logs still get them.)
  • A GET mustn't change anything. Browsers prefetch links, email scanners follow them, and search engines crawl them, so a link like ?delete=42 will get followed by something that never meant to delete anything. That's the server's job to prevent: change things only on a POST, and refuse to on a GET.
  • They have a length limit. Around 2,000 characters is safe everywhere. Big data goes in a POST body instead.

    • If a page shows a search, a filter, a sort order or a page number, keep it in the query string. Then the Back button works, a reload shows the same thing, and a bookmark or a pasted link brings someone exactly where you were.
