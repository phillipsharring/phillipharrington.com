Magic Numbers in Code Phillip Harrington

Good Variable Names left a 7 in the middle of its tidy code. You can guess it means a week, from the line around it. But you had to guess, and the next number won't be that easy. A number like that, with no name, is a magic number: it works, and nobody can say why.

What's a Magic Number?

A literal value in code whose meaning isn't in the code. if ($status === 3). $total * 0.0725. 86400 * 30. Each is a fact about your business or the world, written as if it were obvious, in a place where nobody will find it when it changes.

The fix is a name: a constant for a fixed value, an enum for a set of choices. Then $status === 3 becomes $status === OrderStatus::Shipped, and the line explains itself.

What Isn't Magic

Numbers whose meaning is the number itself. 0 and 1 as starting points, / 100 to turn cents into dollars, 2 in "split in half." If a reader would never ask "why that number?", it doesn't need a name. The same goes for strings: 'admin' scattered through the code is a magic string, and gets the same fix.

Files have magic numbers too, on purpose. Every Java class file starts with the bytes CA FE BA BE. A PNG starts with 89 50 4E 47 (the last three are "PNG" in ASCII), a PDF with %PDF-, a GIF with GIF87a or GIF89a. The Unix file command, and PHP's finfo, read those first bytes to tell what a file really is, whatever its name says. How It Works
  1. Find a literal whose meaning you had to work out.
  2. Give it a name that says what it is, units included: RETURN_WINDOW_DAYS, not THIRTY.
  3. Declare it once, in a place made for declaring things. Use the name everywhere the number was.
  4. When the number changes, change it there. Every use follows, including the ones you forgot existed.

In PHP
  • const NAME = value; declares a constant at the top level of a file or in a class. define('NAME', value) does the same at run time, for the rare constant whose name or value isn't known until then.
  • Backed enums (PHP 8.1) for a fixed set of choices. OrderStatus::from(3) throws on an unknown value; OrderStatus::tryFrom(3) returns null, for when you'd rather decide yourself.
  • Store the enum's value in an ordinary column, an INT or a VARCHAR, and let the PHP enum hold the list of what's allowed. Not a MySQL ENUM column: changing its list means altering the table.
  • PHP's own functions do this already: JSON_THROW_ON_ERROR, E_ALL, PHP_INT_MAX. Nobody writes the numbers they stand for.
  • Underscores in numbers (PHP 7.4) make long ones readable: 1_000_000 is a million, at a glance.
    • Gotchas
  • A constant named after its value isn't a fix. const SEVEN = 7; says nothing 7 didn't. Name the meaning.
  • Some "constants" are really settings. A tax rate depends on where you are and changes when the law does. Values like that belong in configuration, not in code; see Configuration and the Environment.
  • 86400 isn't always a day. In a time zone with daylight saving time, two days a year are 23 or 25 hours long. ->modify('+30 days') on a DateTimeImmutable counts calendar days, which is usually what you meant.
  • The same number can mean two things. A 30-day return window and a 30-day trial are different constants that happen to agree today. Give them two names, so changing one doesn't change both.

    • Write const SESSION_LIFETIME_SECONDS = 30 * 24 * 60 * 60;, not 2592000. PHP works it out once, when the file loads, and anyone reading it can see it's 30 days without reaching for a calculator.
