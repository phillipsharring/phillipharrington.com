Declaring Symbols vs. Causing Changes Phillip Harrington

Magic Numbers split its code in two: rules.php only declared things, and after.php only did things. That's a rule of its own, and one of the first in PSR-1: a file should either declare symbols or cause side effects, and not both. It sounds fussy. It's the reason you can require a file without wondering what it will do to you.

What's Declaring a Symbol?

Giving something a name, for later: a function, a class, an interface, an enum, a constant. Declaring doesn't run anything. Loading a file that only declares changes nothing until someone calls what's in it.

What's Causing a Change?

Anything that makes a difference the moment the line runs. These are side effects:

  • output: echo, HTML outside <?php, header()
  • settings: ini_set(), date_default_timezone_set()
  • files, logs and databases: writing, connecting, querying
  • session_start(), setting a cookie, sending an email
  • changing a global variable
    •  PSR-1 says a file SHOULD do one or the other, in capitals. The capitals come from RFC 2119, written by Scott Bradner in 1997, which pinned down exactly what MUST, SHOULD and MAY mean in a standard. MUST is a requirement. SHOULD means you need a good reason not to. Most internet standards, and every PSR, use those words that way. How It Works
    1. Files that declare hold your functions and classes. One class per file, once you use Composer's autoloader.
    2. A few files cause: the entry points, like public/index.php or a command-line script. They set things up, then call what was declared.
    3. An entry point requires (or autoloads) the declaring files it needs. Requiring them is always safe, from anywhere, any time, in any order.

    The payoff is that a declaring file can be used by something its author never pictured: a test, a command-line job, another page. If loading it also printed a nav bar or started a session, every one of those would get the nav bar too.

    In PHP
  • require and include run the whole file, top to bottom, every time. Declarations are the only lines that are safe to run that way.
  • require_once loads a file only the first time. A declaring file loaded twice with plain require dies with "Cannot redeclare."
  • Composer's autoloader requires a class's file the first time the class is used, which could be at any point. That only works if loading the file has no effects.
  • PHP_CodeSniffer's PSR-12 check, from Coding Standards, warns about a file that does both.
    • Gotchas
  • Whitespace outside <?php is output. A blank line before the opening tag, or after a closing ?>, gets sent, and then header() fails with "headers already sent." It's why PSR-12 says to leave the closing tag off.
  • A constructor that connects is a side effect too. A class whose constructor opens a database connection does it the moment anything makes one. Pass the connection in instead; that's Dependency Injection.
  • declare(strict_types=1) isn't a side effect. It's a setting for the file it's in, and it belongs at the top of every file, declaring or causing.

    • To check that a file only declares, load it and do nothing else: php -r 'require "after/text.php";'. It should print nothing, write nothing and take no time. Anything it does, you'll see.
