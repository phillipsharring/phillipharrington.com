SQL Phillip Harrington

Working with a Database sent queries from PHP and got rows back. The queries themselves were strings in another language: SQL. This section is about that language, and about the database on the other end. PHP's job is small: hand SQL to the database, safely, and do something with what comes back. Most of the real work happens on the database's side.

What's SQL?

A language for asking a database for data and for changing it. Nearly every relational database speaks it: MySQL, MariaDB, PostgreSQL, SQLite, SQL Server, Oracle. Each has its own dialect, but the core is the same everywhere. This course uses MySQL 8.4.

SQL is declarative. You say what you want ("the books from before 1900, oldest first"), not how to find it. The database works out the how, and it's usually better at that than you would be.

Tables, Rows and Columns

A database holds tables. A table is a grid: each column is one kind of fact, with a name and a type, and each row is one thing. A books table might have the columns id, title, author and year, and a row for each book.

The Four Statements

Almost everything an app does to its data is one of four statements:

  • SELECT reads rows.
  • INSERT adds rows.
  • UPDATE changes rows that are already there.
  • DELETE removes rows.
    •

    Each one gets its own lesson in this section, because each has its own way to go wrong. A fifth kind, statements like CREATE TABLE, changes the shape of the database rather than the data in it. That's the next lesson.

    How It Reads SELECT `title`, `year` FROM `books` WHERE `year` < 1900 ORDER BY `year`;

    SQL doesn't care about case or line breaks in its keywords, so the style is up to you. This course writes keywords in capitals, puts each clause on its own line, and wraps the names of tables and columns in backticks. The backticks tell MySQL "this is a name," so a column called order or year can't be mistaken for a keyword. Text values go in single quotes: 'Jane Austen'.

    SQL started at IBM in the early 1970s, where Donald Chamberlin and Raymond Boyce designed a language for Edgar Codd's new relational model and called it SEQUEL, for Structured English Query Language. The name had to change because a British aircraft company already held it as a trademark, so it became SQL. Half the world still says "sequel," and the other half spells it out. Both are right. How It Works
    1. A client, like PHP or the mysql command, connects to the database server and logs in.
    2. It sends a statement, as text.
    3. The server reads it, and checks that the user is allowed to do what it asks.
    4. It plans how to do it: which table to read first, whether an index can help. The Indexes lesson is about that part.
    5. It runs the plan and answers: rows for a SELECT, a count of the rows it changed for the others, or an error.

    The database is a server, like the web server in Client/Server, and your PHP code is its client. It usually runs on another machine, or in another container, and PHP talks to it over the network.

    Start a real MySQL, put some books in it, and talk to it two ways: by typing SQL straight in, and from PHP. This one needs a few files in a folder. First, compose.yml, which describes two containers: the database, and a PHP that can reach it.

    Then init.sql. MySQL runs it once, the first time it starts, to make a table and fill it:

    Start the database, in the background, and wait until it's ready:

    docker compose up -d --wait db New here: Detached: start in the background and give you your terminal back. Don't return until the containers are up and ready. Start only this one, the container called db in compose.yml.

    Then open the mysql command inside its container, logged in as the user from compose.yml. It warns you about the password on the command line, which is fair: fine for a pretend password on your own computer, never for a real one.

    docker compose exec db mysql -u app -papp-password course Run a command inside the db container, which is already running. MySQL's own command-line client. Log in as the user app. The password, app-password, with no space after -p. With a space, mysql would ask for it instead. The database to use.

    At the mysql> prompt, ask for every book. The semicolon sends it.

    SELECT * FROM `books`;

    Then only some of them, in order:

    SELECT `title`, `year` FROM `books` WHERE `year` < 1900 ORDER BY `year`;

    Add one, fix it, and take it out again, checking with a SELECT after each:

    INSERT INTO `books` (`title`, `author`, `year`) VALUES ('Beloved', 'Toni Morrison', 1986); UPDATE `books` SET `year` = 1987 WHERE `title` = 'Beloved'; DELETE FROM `books` WHERE `title` = 'Beloved';

    Each one answers with how many rows it changed: Query OK, 1 row affected. Type exit to leave. Now the same kind of question from PHP. Make db.php, which connects, using the settings compose.yml passes in:

    And books.php, which lists the books from before a year you give it:

    Run it in the PHP container:

    docker compose run --rm php php books.php 1900 New here: Start a fresh container for the php service, with everything compose.yml gives it, and remove it when it's done. The command to run in it, as usual.

    Five books, oldest first, and Charlotte Brontë with her accent intact, because every hop (the file, the connection, the table) is UTF-8. Text and UTF-8 is why that matters, and Character Sets and Collation is the database's side of it. Then try books.php "1900 OR 1=1": it refuses. The year came from the command line, and never trust input, so it's checked before it goes anywhere near the query, and then sent separately from the SQL anyway.

    When you're done, stop it all and throw the data away:

    docker compose down -v Stop and remove the containers. And the volumes: where the database kept its data. (Not the same -v as in docker run.)

    In PHP
  • $pdo->prepare($sql), then execute([$value, ...]), for any SQL with a value in it. The ? marks where each value goes, and the values travel apart from the SQL.
  • $pdo->query($sql) only for SQL with nothing from outside in it at all.
  • foreach ($statement as $row) walks the rows; fetchAll() gets them all at once, and fetchColumn() gets one value.
  • PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION makes a failed query throw, instead of quietly returning false. It's the default since PHP 8.0; the example says it anyway.
  • charset=utf8mb4 in the connection string, every time.
    •  Gotchas
  • Never build SQL out of input. Gluing a value from a form or a URL into the SQL string lets whoever sent it rewrite your query. Never trust input: use placeholders, always. SQL Injection, in Security, shows what happens if you don't.
  • Single quotes for text, backticks for names. MySQL also accepts double quotes for text, but standard SQL, and other databases, read double quotes as names. Stick to single quotes and your SQL means the same thing everywhere.
  • It's one equals sign. WHERE `year` = 1851, not ==. And nothing equals NULL, not even NULL; that's in Selecting Data.
  • Table names can be case sensitive. MySQL stores each table as files on disk, so on Linux Books and books are two different tables, and on a Mac they usually aren't. Code that works on your laptop can fail on the server. Pick lowercase names and never vary them.
  • init.sql only runs on an empty database. Change it, and nothing happens until you throw the old data away with docker compose down -v and start again.

    • In the mysql command, end a query with \G instead of ;, and each row prints as a list of column: value lines instead of one wide line. When a table has more columns than your terminal has room for, it's the difference between reading the answer and squinting at it.
