JavaScript Phillip Harrington

HTML is what the page is, and CSS is how it looks. JavaScript is what it does once it's in the browser: open a menu, check a field as you type, fetch new data without loading a new page. It's a whole language, and this course won't teach all of it. What a PHP developer needs is where it runs, what it can be trusted with, and how to hand it data.

What's JavaScript?

A programming language built into every browser. PHP runs on your server, once per request, and is finished before the page arrives. JavaScript runs on the visitor's computer, after the page arrives, for as long as the page is open. It can change anything on the page, react to clicks and typing, and make requests of its own.

It runs on the visitor's computer, so the visitor controls it. They can read every line, change it, or turn it off. Anything JavaScript checks, the server checks again. Anything in JavaScript, every key and every rule, is public.

The DOM

The tree of elements the browser built from the HTML, from the HTML lesson. JavaScript sees the page as that tree: document.getElementById('size') finds an element, and changing it changes the page on the spot.

Events

Things that happen: a click, a key, a form being sent, the page finishing loading. element.addEventListener('change', ...) says what to run when one happens. Most of the JavaScript on a page is waiting for one.

Brendan Eich wrote the first version of JavaScript at Netscape in about ten days in May 1995. It was called Mocha, then LiveScript, and then JavaScript, a name chosen while Java was the most talked-about language around. Apart from the name and some syntax, the two have little in common. The standard version is called ECMAScript, after Ecma International, which published it in 1997. How It Works
  1. The HTML names a script: <script src="/app.js" defer></script>.
  2. The browser fetches it, like a stylesheet. defer says to run it after the whole page has been read, so the elements it looks for exist.
  3. The script runs, finds the elements it needs, and sets up what to do when events happen.
  4. The visitor does something, and the matching code runs and changes the page.

A script often needs data from PHP: a name, a list, a setting. The safe way is to print it into the page as JSON, inside a <script type="application/json"> tag, which the browser stores but doesn't run, and have the script read and parse it. The danger is the data itself. If a value contains </script>, it closes the tag early, and whatever follows is HTML, and maybe a script of the visitor's choosing. Never trust input, not even on its way into JavaScript.

Open http://localhost:8000/?name=Alice and pick a size. The menu wasn't in the HTML PHP sent: JavaScript built it from the data. Now try to break out of the script tag:

curl 'http://localhost:8000/?name=%3C/script%3E%3Cscript%3Ealert(1)%3C/script%3E'

In the data, every < and > has become \u003C and \u003E: still the same characters to JavaScript once it's parsed, but nothing the HTML reader can mistake for a tag. Open the same URL in the browser, pick a size, and the sentence shows the name as text, tags and all. That's textContent. Had the script used innerHTML, the browser would have read the name as HTML.

In PHP
  • json_encode($data, JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT | JSON_THROW_ON_ERROR) for any data printed into a page for JavaScript. The JSON lesson is the rest of it.
  • data- attributes are the other safe way, for a value or two: <div data-name="<?= htmlspecialchars($name) ?>">, read in JavaScript as element.dataset.name.
  • Never paste a value straight into script code, like let name = '<?= $name ?>';. One apostrophe in the name, and the visitor is writing your JavaScript.
    • Gotchas
  • Checks in JavaScript are a courtesy. Like the browser's checks in Forms, they save honest visitors a round trip, and stop nobody else. The server checks everything again.
  • Everything in JavaScript is public. An API key in a script is readable by anyone who opens the developer tools. Keys stay on the server, and the browser asks your server, which uses them.
  • innerHTML runs HTML. Use textContent for anything from outside. If you must build HTML, escape it the way you would in PHP.
  • A script that runs too early finds nothing. Without defer, a script in the head runs before the body exists, and getElementById() returns null.
  • Not everyone has it. Scripts fail to load, get blocked, or break. Links and forms that work without JavaScript keep working when it doesn't.

    • Open the developer tools (F12, or Cmd+Option+I on a Mac) and leave the Console tab showing while you work. A JavaScript error doesn't show on the page; the page just stops working. The console says what broke and on which line.
