Scope Phillip Harrington

A variable doesn't exist everywhere. Set one at the top of a file, and a function further down can't see it. Set one inside a function, and it's gone when the function returns. Where a variable can be seen is its scope, and PHP's rules for it are short. They're also a feature: a function that can only see what you hand it is a function you can understand.

What's Scope?

The part of your code where a variable can be seen. PHP has a few:

The Global Scope

Variables set outside any function, at the top level of a file, are in the global scope. Every file pulled in with an include shares it too, which Includes covers.

A Function's Scope

Each function starts empty. It sees its own parameters and whatever it makes, and nothing from outside. When it returns, its variables are thrown away. The next call starts empty again.

The Superglobals

A handful of variables PHP fills in for you are visible everywhere, inside functions too: $_GET, $_POST, $_COOKIE, $_SERVER, $_FILES, $_ENV, $_SESSION, and $GLOBALS. Most of them are input, straight from the request.

Closures

A function without a name, kept in a variable, is a closure. It can borrow variables from the scope where it was made, but only ones you name with use: function ($name) use ($greeting) { ... }. An arrow function, fn($name) => $greeting . $name, borrows whatever it uses automatically. Both take a copy of the value at the moment they're made.

Early PHP had a setting called register_globals, which turned every query string and form field into a global variable. Visit ?admin=1, and the script started with $admin set to '1'. Code that checked if ($admin) without ever setting it to false let anyone in. It was turned off by default in PHP 4.2, in 2002, and removed entirely in PHP 5.4. How It Works
  1. Your file starts running in the global scope.
  2. A function is called. PHP gives it a fresh, empty scope, and puts the arguments in it as its parameters.
  3. The function works with those and the superglobals. It can't reach the caller's variables, and the caller can't reach its.
  4. It returns a value, and its scope is thrown away.
  5. The caller carries on, with its own variables untouched.

Ifs and loops don't make a scope. A variable set inside a foreach is still there after it, holding whatever it had last. That's different from many other languages, and it's the source of the gotcha below.

A function can reach out with global $site; or $GLOBALS['site']. Don't. A function that reads and writes globals can be changed by any line anywhere in the program, so you can't understand it by reading it. Pass in what it needs; return what it makes.

Try It

Every rule above, one after another. In a folder, make scope.php:

docker run --rm -v "$PWD":/app -w /app php:8.4-cli php scope.php

welcome() can't see $site; welcome_to() gets it as a parameter. $visits never leaves count_visit(). $_SERVER works anywhere. $size outlives its loop. And both closures say "Hi," not "Goodbye," because they copied $greeting when they were made.

Now the trap a leftover loop variable sets. reference.php:

docker run --rm -v "$PWD":/app -w /app php:8.4-cli php reference.php

The prices should be 200, 400, 600. The last one is 400. After the first loop, $price is still a reference to the last item, so the second loop wrote each price into it in turn, ending with the one before it.

In PHP
  • Parameters in, return out: the normal way to share.
  • function (...) use ($a, $b) { ... }: a closure, with the variables it borrows named.
  • fn(...) => ...: an arrow function, which borrows what it uses.
  • unset($x): throw a variable away, which is how you end a loop's reference.
  • static $count = 0; inside a function keeps a value between calls. Constants, Static Variables and Functions has more.
    • Gotchas
  • A foreach with & leaves a reference behind. Use the same name in a later loop, and you overwrite the last item. unset() it right after the loop.
  • A loop variable keeps its last value. Code after the loop that uses $item by accident gets the last one, not an error.
  • A missing variable is a warning, not a stop. Forget to pass something in, and the function gets null and a warning, and keeps going. Errors and the Error Log is about seeing those.
  • The superglobals are input. Being visible everywhere makes $_GET easy to use deep inside a function, where nobody remembers to check it. Never trust input: read it in one place, check it there, and pass the checked value in.

    • A long script at the top level fills the global scope with every variable it ever made, all visible to each other and to every file it includes. Put the work in a function main(): void and call main(); at the bottom. Nothing leaks, and a typo in a variable name shows up as a warning instead of quietly reading some leftover.
