Anatomy of a URL Phillip Harrington

In Client/Server you opened http://localhost:8000. That's a URL, a Uniform Resource Locator: one line of text that tells a client which protocol to speak, which server to talk to, where to knock, and what to ask for. Every link you've ever clicked is one. Here's a full one, with every part filled in:

https://www.example.com:8080/blog/post?sort=new&page=2#comments There's one more part, almost never seen: a user name and password before the host, as in https://user:pass@www.example.com/. It puts a password in plain sight, and it's an old phishing trick: https://www.example.com@evil.example/ looks like example.com, but everything before the @ is the "user name," and the browser goes to evil.example. Browsers warn about it or strip it now. Know it when you see it, and never build one. The Parts Scheme: https

Which protocol to use. https and http for the web, but there are others: mailto: opens your email program, file: opens a file on your own computer.

Host: www.example.com

Which server. A name, which DNS turns into an address, or the address itself. The www is a subdomain the owner chose, nothing more.

Port: 8080

Which door on that server. You almost never see one, because each scheme has a default: 80 for http, 443 for https. Leave it off, and the browser uses the default. Your Try It server needed :8000 because it wasn't on either.

Path: /blog/post

Which thing on that server. It looks like folders and a file, and sometimes it is, but each server decides what a path means. In a PHP app, every path usually goes to one script that decides what to show.

On this site, /about is a file with no extension.

 Query String: ?sort=new&page=2

Extra instructions for the server, after a ?: pairs of name=value, joined with &. Here, "sort by newest, show page two." In PHP they arrive in $_GET. Query strings get a lesson of their own.

Fragment: #comments

After a #, the name of a spot on the page. If the page has an element with that id, the browser can scroll to it. And it never sends the fragment to the server: it's the one part of a URL that stays in your browser.

Tim Berners-Lee, who invented the web, has said the // after the scheme was unnecessary, and that he'd leave it out if he did it again. Since then, the world has typed it billions of times, for nothing. How It Works

When you follow a link, the browser takes the URL apart, left to right:

  1. The scheme says which protocol to speak.
  2. The host gets looked up in DNS, to find the server's address.
  3. It connects to that address on the port, or the scheme's default.
  4. It asks the server for the path, with the query string attached.
  5. When the page arrives, it scrolls to the fragment.

Some characters can't go in a URL as themselves: a space, or an & that's part of a value rather than a separator. They're written as a % and two hex digits instead. A space is %20. That's percent-encoding, and it's why some links look like they were typed by a cat.

Links inside a page usually leave off the scheme, host and port, and start with just the /. A link to /about on this site means "same scheme, same host, this path", and the browser fills in the rest from the page you're on. That's a relative URL.

In PHP
  • parse_url() takes a URL apart.
  • $_SERVER['REQUEST_URI'] is usually the path and query string of the request you're answering, and $_GET is its query, already decoded.
  • http_build_query() goes the other way: it turns an array into a query string, percent-encoding as it goes.
  • rawurlencode() encodes one value to put in a path.
    •  Gotchas
  • The server never sees the fragment. Anything after the # stays with the page: the browser can scroll to it, and JavaScript in the page can read it, but PHP never sees it.
  • Build query strings, don't glue them. A value with an & in it ("Salt & Pepper") breaks a query string assembled by hand. http_build_query() encodes it for you.
  • parse_url() doesn't check anything. It splits whatever you give it, as well as it can. To ask whether something is a valid URL, use filter_var($url, FILTER_VALIDATE_URL).
    • The first website lived at info.cern.ch, no www in sight. The www caught on as a convention, a way of saying "the web server is this machine," and stuck around long after it stopped meaning anything.
