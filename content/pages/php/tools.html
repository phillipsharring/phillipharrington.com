Tools Phillip Harrington

These aren't lessons. They're the handful of things you set up once and come back to when a lesson needs them. The course assumes you can install an app and find a folder on your computer, and nothing more: if you've never opened a terminal, start at the top.

One rule runs through all of it: you install as little as possible on your own computer. Docker is the one real install. Everything else, PHP included, runs in a container.

The Terminal

A window where you type commands instead of clicking. On a Mac it's Terminal, in Applications, Utilities. On Windows it's Windows Terminal, which runs PowerShell. On Linux, you already know.

Four things get you a long way:

  • pwd says which folder you're in.
  • ls lists what's in it (dir also works on Windows).
  • cd some-folder goes into a folder, and cd .. goes back up.
  • Ctrl+C stops whatever is running.
    •

    The up arrow brings back the commands you typed before.

    It's called a terminal because it used to be one: a screen and keyboard wired to a computer somewhere else, like DEC's VT100 from 1978. The window on your screen is still pretending to be one, codes and all. Docker

    Docker runs containers: small, sealed-off computers-in-a-box with exactly the software a lesson needs. When you're done, the box goes away, and nothing was installed on your machine. It's how every lesson runs PHP.

    Get Docker Desktop on a Mac or Windows. On Linux, install Docker Engine with your package manager. Docker Desktop has to be running before any docker command works. Check it:

    docker run --rm hello-world

    If it prints "Hello from Docker!", you're set. One Windows difference: where a lesson says "$PWD" (the folder you're in), PowerShell wants ${PWD}.

    Package Managers

    For the few things that do have to live on your computer, use your system's package manager rather than downloading installers from websites. It installs, updates and removes things with one command each.

  • Mac: Homebrew. For example, brew install git.
  • Windows: winget, built in. For example, winget install Git.Git.
  • Debian and Ubuntu Linux: apt, built in. For example, sudo apt install git.
    • Git

    Git keeps the history of your code: every change, when, and why, so you can go back. Install it with your package manager (above). Check it:

    git --version

    The lessons use a few Git commands as they come up. For the whole thing, the free Pro Git book is the one.

    Your Editor

    Code is plain text, so you need a code editor, not a word processor. VS Code is free and fine. If PHP turns into your job, PhpStorm is worth paying for. Any editor works for the course.

    Reading Logs

    A log is a file a program writes lines to as things happen. Watching one while you click around is half of debugging. To follow a log as it grows:

    tail -f some.log

    less +F some.log does the same, and lets you scroll back: Ctrl+C to stop following, q to quit. lnav, from your package manager, adds color and search. On Windows, Get-Content some.log -Wait in PowerShell follows a file, or try BareTail. For a container, docker logs -f and the container's name.

    Composer, in a Container

    Composer is PHP's package manager: it fetches the libraries a project uses. You'll run it in a container too, never installed:

    docker run --rm -it -v "$PWD":/app -w /app composer:2 composer install

    The lessons that need it say so, and explain it there.

    Type the first few letters of a file, folder or command and press Tab: the terminal finishes it for you. Fewer typos, less typing, and if nothing happens, the thing you're typing doesn't exist where you think it does.

    That's everything. Now the first real lesson: how two computers talk at all.
