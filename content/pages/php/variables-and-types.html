Variables, Types and strict_types Phillip Harrington

Output printed names, prices and lists, and every one of them was held in a variable first. A variable is simple. The interesting part is the value inside it, because every value has a type, and PHP will quietly change a value's type when it thinks you meant it to. Sometimes that helps. Sometimes it hides a bug. One line at the top of a file decides which.

What's a Variable?

A name for a value. In PHP it starts with $, then a letter or underscore, then any letters, numbers and underscores: $name, $order_total, $item2. You make one by assigning to it, with a single =:

$name = 'Alice'; $count = 3;

There's no separate step to declare it. Names are case-sensitive, so $name and $Name are two variables. Using one that was never assigned gets a warning, "Undefined variable," and the value null.

What's a Type?

The kind of value something is. The everyday ones are int (a whole number), float (a number with a decimal point), string (text), bool (true or false), array, and null (nothing). Types of Types takes them one at a time.

In PHP the type belongs to the value, not the variable. Put a string in $count after a number, and $count holds a string now.

Type Juggling

When an operation needs a certain type, PHP converts the value to fit. + needs numbers, so '5' + 5 is 10. . joins strings, so '5' . 5 is "55". The manual calls this type juggling.

Type Declarations

A function can say what types it takes and gives back. This one takes an int and returns an int:

function double(int $number): int

By default, PHP juggles here too: pass it the string '21', and it's converted to 21 on the way in. Functions covers the rest of that line.

strict_types

This line, as the very first statement in a file, turns that conversion off:

declare(strict_types=1);

Now an int parameter takes an int, and anything else is a TypeError that stops the script. (One small exception: an int is still accepted where a float is expected.) It's per file, and it covers the calls made from that file. From here on, every example in the course starts with it.

PHP started out replacing a few Perl scripts, and it borrowed from Perl's syntax, the $ included. Perl had it from Unix shell scripts, where $name means "the value of name." Shell scripts only use the dollar when they read a variable. PHP uses it every time, which is simpler to remember. How It Works

When you call a function that declares a type, PHP checks the value you pass:

  1. If the value is already the right type, it goes in.
  2. If not, PHP looks at the file the call is in. Without strict_types, it tries to convert the value: '21' becomes 21, true becomes 1.
  3. If it can't convert it, like 'twenty-one', or the file has strict_types, it's a TypeError.
  4. The return value is checked the same way on the way out.

That matters most for input. Every form field, query string, cookie and header arrives as a string, even when it looks like a number. Arithmetic and casts would quietly turn '21abc' into 21. With strict_types, a string can't wander into a function that wants an int. You have to check it and convert it on purpose, which is exactly what you should be doing anyway. I'll say it again, in case it's been a few pages: never trust input.

The loose one doubles 21, '21' and even true, and only gives up on 'twenty-one'. The strict one stops at '21', with "must be of type int, string given," and the line it happened on.

So input has to be converted by hand. input.php takes what you type after the file name, which arrives as a string just like a form field:

docker run --rm -v "$PWD":/app -w /app php:8.4-cli php input.php 21 docker run --rm -v "$PWD":/app -w /app php:8.4-cli php input.php 21abc

As in DNS: whatever follows the file name reaches the script as an argument, here 21 and then 21abc.

The cast, (int), turns 21abc into 21 without a word. filter_var() with FILTER_VALIDATE_INT checks the whole string, and says no.

In PHP
  • declare(strict_types=1); as the first statement of every file.
  • var_dump($x) shows the type and value. get_debug_type($x) gives just the type's name, for an error message.
  • isset($x): whether a variable exists and isn't null, with no warning.
  • filter_var($input, FILTER_VALIDATE_INT): the whole string is a whole number, or you get false. There are flavors for floats, emails, URLs and more.
  • (int), (float), (string), (bool): casts. They always succeed, which is the problem with using them on input.
    • Gotchas
  • strict_types is per file. It has to be in every file, and it covers the calls that file makes. A file without it can still pass a string to your strict function, and PHP will convert it.
  • It has to be first. Put any code before it, and PHP refuses to run the file. Comments are fine.
  • Casting isn't checking. (int) '21abc' is 21, and (int) 'abc' is 0. A cast on input turns garbage into a plausible number. Validate first.
  • Input is always a string, or an array. Even ?id=7 gives you '7', and ?id[]=7 gives you an array. Check the type before you use it.

    • Most editors let you change what a new PHP file starts with. Make it <?php, a blank line, and declare(strict_types=1);. You'll never forget it again, and you'll never have a file where half the calls are quietly juggled.
