Working with a Database: PDO and Prepared Statements Phillip Harrington

Working with Files ended at the limits of a text file. A database is the next step: a separate server that stores your data, finds any piece of it fast, and lets many requests read and write at once. PHP talks to it with PDO. This lesson is about the connection and the one habit that matters from the very first query: the query and the input travel separately, always.

What's a Database?

For this course, MySQL: a server, like a web server, that PHP connects to over the network. It keeps data in tables of rows and columns, and you ask it for things in a language called SQL. SQL, next, and the whole Database section after it, are about that language and those tables. This lesson is just getting PHP and MySQL talking.

What's PDO?

PHP Data Objects: PHP's built-in way to talk to databases. The same functions work with MySQL, PostgreSQL, SQLite and others, each through a driver. PHP's Docker image comes with the SQLite one; MySQL's, pdo_mysql, takes one line to add.

The Connection

new PDO($dsn, $user, $password, $options). The DSN, a data source name, says which driver, where, and which database:

mysql:host=db;dbname=course;charset=utf8mb4

charset=utf8mb4 makes the connection itself UTF-8, real UTF-8, emoji included, as Text and UTF-8 said. Recent versions default to it, older ones don't, so say it, and the connection is never the place text gets mangled. The user and password come from the environment, never from the code, as in Configuration and the Environment.

The Options
  • PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION: a failed query throws an exception instead of quietly returning false. It's the default since PHP 8.0; say it anyway.
  • PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC: each row comes back as an array with the column names as keys.
  • PDO::ATTR_EMULATE_PREPARES => false: prepared statements are done by MySQL itself, not imitated by PHP.
    • Prepared Statements

    A query with blanks in it, called placeholders, and the values sent separately:

    $insert = $pdo->prepare('INSERT INTO books (title, author) VALUES (:title, :author)'); $insert->execute(['title' => $title, 'author' => $author]);

    :title is a named placeholder. A plain ? works too, with the values in order. Either way, whatever is in $title, quotes, SQL, anything, is stored as a title. It can't become part of the query, because the query was already settled before the value arrived. That's the defense against SQL injection, and it's the only way this course ever puts a value into SQL.

    PHP's first MySQL functions, mysql_connect() and mysql_query(), took a query as one string, so the natural way to add a value was to glue it in. A generation of tutorials did exactly that, and a generation of sites were open to SQL injection. PDO arrived in PHP 5.1, in 2005, with prepared statements. The old functions were deprecated in PHP 5.5 and removed in PHP 7.0. How It Works
    1. new PDO(...) connects to MySQL over the network and logs in. In Docker Compose, the host is the database service's name, db.
    2. prepare() sends the SQL, placeholders and all. MySQL reads it and works out what it will do, before it has seen a single value.
    3. execute() sends the values. MySQL drops them into the blanks as data, and runs the query.
    4. fetch() or fetchAll() brings the rows back, as arrays.
    5. The connection closes when the script ends.

    So the attacker's favorite trick, a quote that ends your string and starts their SQL, has nothing to work on: by step three, there's no SQL left to change. Never trust input, and never glue it into a query, not once, not even a number you've checked.

    In PHP
  • new PDO($dsn, $user, $password, $options), with charset=utf8mb4 in the DSN and the three options above.
  • $pdo->prepare($sql) then $statement->execute($values): every query with a value in it.
  • fetch() for one row (or false if there isn't one), fetchAll() for all of them, fetchColumn() for one value.
  • $pdo->lastInsertId(): the id MySQL just gave a new row.
  • $statement->rowCount(): how many rows an UPDATE or DELETE changed.
  • getenv('DB_PASSWORD'): the settings, from the environment.
    •  Gotchas
  • Never glue input into SQL. Not "just this once," not a number you cast, not an id from your own link. Placeholders, every time, so you never have to decide whether this one was safe.
  • Placeholders are for values only. A table name, a column name, or ASC and DESC can't be placeholders. When those come from a visitor, like a "sort by" link, pick from an allow list of your own exact strings.
  • LIKE has its own wildcards. % and _ in a search mean "anything," so a search for % matches every row. Escape them, as the example does with addcslashes().
  • A named placeholder can't be used twice. With real prepared statements, :pattern twice in one query is an error. Give each its own name, like :in_title and :in_author.
  • What comes out of the database is input. It got in from somewhere. Escape it on the way into HTML, every time, or the database delivers a stored attack to every visitor: XSS.
  • Connection errors can leak. A failed new PDO() throws an exception whose message names the database user, and sometimes the host. With display_errors off, as Errors and the Error Log said, it goes to the log, not the page.
    • One of my apps had seed scripts: SQL that fills a fresh database with starting data, like init.sql here. One of them created an admin account, admin@example.com, with the password password. Handy on a laptop. But the seeds ran on production deploys too, until they were stopped. Starting data is code that runs against your real database, so check where it runs. Repeated side story: the seed admin story (admin@example.com / password on production) is also told in Configuration and the Environment. Keep one, make this a callback, or cut it.

    $pdo->query('SELECT id, title FROM books ORDER BY title')->fetchAll(PDO::FETCH_KEY_PAIR) gives you [id => title], ready for a select menu. (Plain query() is fine here because there's no value in the SQL. The moment there is one, prepare().)
