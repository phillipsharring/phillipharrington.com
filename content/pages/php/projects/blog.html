Blog Phillip Harrington

The CMS held pages that stay where you put them. A blog holds posts that arrive in order. You'll build the reading side of one: a list, newest first, three to a page; a page for each post; drafts and scheduled posts that nobody sees until their time; and an Atom feed, so people can follow along in a feed reader without visiting at all.

Writing posts is the CMS's admin form with a date on it, so this project leaves it out and puts the posts straight into the database.

What You'll Use
  • Content Management System: pages from a table, plain text to paragraphs
  • Selecting Data: ORDER BY, LIMIT and OFFSET
  • Indexes: on the column every query sorts by
  • Query Strings: ?page=2, which is input
  • Content Types: the feed isn't HTML

    Step 3: The Pages

    public/index.php answers three kinds of address: / for the list, /posts/hello for a post, and /feed for the feed. Anything else is a 404.

    I'll keep this short, since you know it by heart: never trust input, including the page number. ?page=abc, ?page=-3 and ?page=1 OR 1=1 all become page 1, through filter_var(), before they get anywhere near SQL. A page past the end is a 404. So is a draft, the same answer as a typo, so the blog doesn't confirm that an unpublished post exists.

    Step 4: The Feed

    A feed is an XML file listing the latest posts, which feed readers check now and then. src/feed.php builds one in the Atom format with XMLWriter, which escapes every value as it writes it:

    Feed links must be whole URLs, with the scheme and host. They come from SITE_URL, a setting, never from the request's Host header. The Host header is input: anyone can send Host: evil.example, and a feed built from it, cached and served to everyone, would point your readers at someone else's site.

    Step 5: Run It docker compose up

    A reminder: docker compose up starts every container the project's compose.yml lists, together.

    Open http://localhost:8000. Five posts are live, three on the first page, two on the second. The title with <b> in it shows the tags as text. Then try the ones you shouldn't see:

    curl -i http://localhost:8000/posts/unfinished curl -i http://localhost:8000/posts/someday curl http://localhost:8000/feed

    Two 404s, and a feed with five entries. Change someday's published_at to a minute from now with docker compose exec db mysql -uapp -papp-password course, wait a minute, and it appears, with nothing else to do.

    Jorn Barger called his site of daily links a "weblog" in 1997. In 1999, Peter Merholz jokingly split the word as "we blog," and "blog" stuck, as a noun and a verb. The Atom format came later, in 2005, as RFC 4287, written partly to settle the confusion between the several incompatible versions of RSS. Gotchas
  • Offsets get slow, and they shift. OFFSET 10000 makes the database find and skip ten thousand rows. And a new post pushes everything down one, so a reader paging back sees one post twice. For long lists, page by "older than this date" instead.
  • Pick UTC and never change it. Store UTC, set the connection to UTC, and convert for display. A server whose time zone changes, or a summer-time switch, will otherwise publish posts an hour early or late.
  • Slugs are forever. Once a post's address is out in the world, changing it breaks every link to it. If you must, keep the old slug and redirect it with a 301.
  • A feed is content too. The same escaping rules apply, and the same hidden posts stay hidden. It's easy to filter drafts out of the page and forget the feed.

    • One line in the <head>, <link rel="alternate" type="application/atom+xml" href="/feed">, and feed readers find the feed from the blog's address alone. People paste the home page into their reader, not /feed.
