Affiliate Program Phillip Harrington

An affiliate program pays people for sending you customers. A blogger links to your product with their own code in the link, and if someone follows it and buys, the blogger gets a cut. You'll build the pieces: the link, the cookie that remembers who sent a visitor, and the commission worked out when an order arrives.

Money is changing hands based on a code in a URL and a cookie in a browser, both of which anyone can edit. So the work is mostly in the checks: which codes count, who can earn on which orders, and how the cents are rounded.

What You'll Use
  • Query Strings: ?ref=ALICE10
  • Cookies and Sessions and Cookie Flags: 30 days of memory
  • Redirecting: a redirect that can't be pointed elsewhere
  • Store Front: money in whole cents
  • Transactions: an order and its commission, together

    The containers, Dockerfile and src/db.php are the usual ones from Translation, with the database called shop. Four tables: the affiliates, their clicks, orders, and commissions:

    Each affiliate's cut is in basis points, hundredths of a percent: 1000 is 10%, 750 is 7.5%. That keeps percentages in whole numbers too, like the money. A commission's order_id is unique, so an order can never pay out twice.

    Step 2: The Rules
  • find() is the gate. A code must have the right shape and belong to an active affiliate, or it's nothing. It's used for the link and again for the cookie, because both are input.
  • commission() multiplies first and divides last, with intdiv(), so 10% of $49.99 is 499 cents. The fraction of a cent is dropped, on purpose and in one place.
  • recordOrder() writes the order and its commission in one transaction, and pays nothing when the buyer is the affiliate.
    • Step 3: The Link

    Someone follows /?ref=ALICE10. If the code is real, the click is counted and a cookie remembers it for 30 days: HttpOnly, so the page's JavaScript can't read it, and SameSite=Lax, which still sends it when someone follows a link from another site. Either way, the visitor is redirected to the plain page.

    That redirect always goes to /, a fixed address. Redirect code that sends people to an address from the query string, like ?next=, is an open redirect, and a link through your site to someone else's is exactly what a phishing email wants.

    Step 4: The Order

    A stand-in for the shop's checkout, with one product at one price. It reads the cookie, looks the code up again, and records the order:

    Never trust input. The cookie came back from the browser, and the browser's owner can set it to anything. An affiliate's code is public, it's in their links, so a cookie can only ever claim what any visitor could claim by clicking one. Codes that aren't real and active count for nothing.

    Step 5: The Report Step 6: Run It docker compose up

    Open http://localhost:8000/?ref=ALICE10. The address changes to http://localhost:8000/, and your browser's developer tools show a ref cookie. Buy the widget, then, from a second terminal:

    docker compose exec app php bin/report.php Code Clicks Orders Pending ALICE10 1 1 $4.99 BOBREVIEWS 0 0 $0.00 OLDPARTNER 0 0 $0.00

    Then the ways it shouldn't pay:

    curl -i 'http://localhost:8000/?ref=OLDPARTNER' curl -H 'Cookie: ref=MADEUP' -d email=gus@example.com http://localhost:8000/buy.php curl -H 'Cookie: ref=ALICE10' -d email=alice@example.com http://localhost:8000/buy.php

    An inactive affiliate's link sets no cookie. A made-up code in the cookie earns nothing. And Alice buying through her own link records the order and pays her nothing. Run the report again: still $4.99.

    Amazon started its Associates program in 1996, paying websites a share of the books sold through their links. It wasn't the first program of its kind, but it was the one that made the idea familiar, and the basic shape, a code in the link and a cut of the sale, hasn't changed since. Gotchas
  • Decide who gets credit, and write it down. This one gives it to the last link followed, because each click overwrites the cookie. Some programs give it to the first. Either is fine; changing it quietly isn't.
  • Commissions wait for refunds. A commission stays pending until the refund window has passed. If the order is refunded first, the commission is reversed. Approving them is a nightly cron job.
  • Clicks are cheap to fake. Anyone can load a link a thousand times. Count clicks for interest, and pay only on orders.
  • Tell people. Many places require affiliates to disclose that they're paid for a link, and your site should say that it tracks referrals with a cookie.
  • Cookies get cleared. Private windows, other devices, browsers that limit tracking. Some referrals will always be lost; build the program expecting it.

    • intdiv($total * $bps, 10000), not $total * ($bps / 10000). Dividing first makes a float, and the rounding happens wherever it happens. Do all the multiplying in whole numbers, divide once at the end, and the rounding is one decision you can point to.

    Affiliates will want their numbers without asking you to run a report. Next: a REST API, where another program asks your server for data, and has to prove who it is.
