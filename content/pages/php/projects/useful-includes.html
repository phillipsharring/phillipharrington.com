Useful Includes Phillip Harrington

A one-page site is easy. The second page is where it starts: the same header, the same navigation, the same footer with its view source link, and the same settings at the top, copied into both. Change the site's name and you change it everywhere, by hand, and miss one.

This project pulls the shared parts into their own files and has every page include them: one bootstrap file that sets things up, a settings file, a couple of helper functions, a header and a footer. All of them live outside public, where only your code can reach them.

What You'll Use
  • Includes: require, require_once, and a file that returns a value.
  • Functions: small helpers you call everywhere.
  • Document Root: __DIR__, dirname(), and keeping code out of public.
  • View Source Link: the viewer, moved in.

    The Viewer, Moved In

    public/source.php is the View Source Link viewer, now using the bootstrap and the templates, with the shared files on its allow list so visitors can see how the pieces fit. Never trust input still applies: the query string picks a key, never a path, and config.php stays off the list.

    Run It docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000 -t public

    Open http://localhost:8000 and click between Home and About. Same header, same footer, and the current page marked in the navigation. Change site_name in config.php and reload: it changes in both pages and both titles. Then try to fetch the shared files through the web:

    curl http://localhost:8000/src/config.php curl http://localhost:8000/templates/header.php

    Neither one is there. They're outside public, so the server can't hand them out, and you get the home page instead.

    Gotchas
  • Relative paths in an include are a guess. require 'src/bootstrap.php' is looked up in several places, the include path and the current directory among them, and the current directory depends on how PHP was started. Build every path from __DIR__.
  • Functions can only be declared once. Include functions.php twice and PHP stops with "Cannot redeclare". That's what require_once is for. Settings files that return a value are the opposite: plain require, since you want the value each time.
  • An include in the web root can be run on its own. Put header.php in public, and anyone can visit it directly, with none of the variables it expects. At best it shows warnings; at worst, paths and settings. And a file named config.inc isn't .php, so the server sends it as text. Keep includes outside public.
  • A header and footer split one tag across two files. The header opens <main> and the footer closes it, and neither file makes sense alone. It works, and it gets fragile as the site grows. The next project fixes it.

    • A bootstrap that every page requires is the place for anything you'd otherwise forget on one page: the time zone, error settings, security headers, starting a session. Put it there once, and the page you add next year gets it for free.
