Comments Phillip Harrington

The blog talks; comments let readers answer. A comment form is the most public input on any site: no login, no account, anyone at all. Two things go wrong with it, and both go wrong fast. Someone posts a script, and it runs in every reader's browser. And bots find the form, and post advertisements into it all day.

You'll build comments on a post, then the naive version, and attack it both ways. The fix for the first is one function used everywhere. The fix for the second is a few small checks stacked up, because no single one stops every bot.

What You'll Use
  • XSS and Escaping Output: escape on the way out, every time
  • Never Trust Input: every field, checked on the server
  • Rate Limiting: so many per address per minute
  • Guestbook: the same stored-script attack, met earlier
  • What's in the Middle: which address is the visitor's
  • Text and UTF-8: refusing bytes that aren't text

    Step 2: The Spam Checks

    src/spam.php holds four small checks:

  • The form token records when the form was shown, signed with hash_hmac() and the secret so it can't be forged. A comment that comes back in under three seconds came from a script; a person has to read first. One older than an hour gets refused, so a bot can't keep one token forever.
  • The rate limit counts this address's comments in the last ten minutes. Five is plenty for a person.
  • The link check holds back comments with more than one link. Links are what most spam is for.
  • The honeypot is in the form itself, in Step 3: a field people never see, that bots fill in because they fill in everything.
    • Step 3: The Post and the Form

    public/index.php shows the post, its approved comments, and the form. Every name and comment goes through htmlspecialchars() on the way out, and nl2br() after, so line breaks survive and nothing else becomes HTML:

    The note at the top comes from a list of our own messages, picked by a word in the URL. The URL never supplies the text itself, or anyone could send a link that puts their words on your page.

    Step 4: Taking a Comment

    public/comment.php runs the checks in order, cheapest first, and stores the comment exactly as typed. Never trust input, but don't change it on the way in, either: storing it raw and escaping it on the way out means the same text works on a page, in an email, or in a feed, each escaped its own way.

    The honeypot answer is a success, on purpose. A bot that gets an error tries something else; a bot that gets "thanks" moves on.

    Step 5: Run It docker compose up

    Open http://localhost:8000, wait a few seconds, and post a comment. Post one with two links in it, and it says it'll appear once someone has read it. Post a few more, and the sixth in ten minutes gets 429 Too Many Requests.

    Break It

    The comments page most people write first:

    First attack: a comment that's a script.

    curl --data-urlencode 'name=Mallory' \ --data-urlencode 'body=<script>alert(document.cookie)</script>' \ http://localhost:8000/naive.php

    Open http://localhost:8000/naive.php in a browser, and an alert pops up. The script ran, in your page, with everything your page can reach. On a site with a login, document.cookie holds the session, unless the cookie is HttpOnly. It'll pop up for every reader, on every visit, until someone deletes the comment. An alert is the polite version. The same spot could send each reader's cookies to another server, rewrite the page, or submit forms as them. This is stored XSS: the attack is saved in your database and served by your own site.

    Second attack: be a bot.

    for i in $(seq 1 20); do curl -s -o /dev/null -d name=Bot -d "body=Buy now $i http://spam.example" http://localhost:8000/naive.php done

    Only the new parts:

    seq 1 20 counts from 1 to 20, and $(...) drops its output into the command, so the loop runs twenty times. Double quotes, so the terminal swaps in the value of $i: each comment gets its own number.

    Reload the naive page: twenty advertisements, posted in about a second, all live.

    Fix It

    Now open http://localhost:8000. The same comment, from the same table, shows up as text: <script>alert(document.cookie)</script>, harmless. The fix was never about what's in the database. It's htmlspecialchars() on every value, every time it goes into a page.

    Then the bot. Point the same loop at comment.php, and none get through: without the form's fields and token, each is refused before anything is saved. A smarter bot that fetches the form first still has to wait three seconds per token, gets cut off after five comments, and its links put every one in the moderation queue instead of on the page. Fill in the honeypot, and it's told "thanks" while nothing is saved.

    Each check stops some bots, and none stops all of them. Stacked, they stop most, and the rest wait for a person.

    In 1978, Gary Thuerk, a marketer at Digital Equipment Corporation, sent one message to a few hundred people on ARPANET, announcing a product demonstration. It's usually counted as the first spam, and it drew complaints at once. The name came much later, from a Monty Python sketch in which a café menu has Spam in nearly everything, and the word drowns out the conversation. Gotchas
  • Escape in the right place for the context. htmlspecialchars() is right between tags and inside quoted attributes. Inside a <script> block, a URL, or CSS, it isn't enough; each has its own escaping. The XSS lesson has the list.
  • Making links clickable invites spam. If you turn URLs in comments into links, add rel="ugc nofollow", so search engines don't count them and spammers gain less.
  • Behind a proxy, every comment has the same address. Then five per ten minutes is five for the whole world. Use the address your own proxy reports, as in What's in the Middle.
  • Honeypots must be hidden from people, and from screen readers. That's the aria-hidden, the tabindex="-1", and autocomplete="off", so a browser doesn't fill it in for a real person.
  • Held comments need a person. A moderation queue nobody reads is a slow way of deleting comments. Build the page that lists them, or don't hold them.

    • Keep a file of inputs that break things: <script>alert(1)</script>, "><b>, ' OR '1'='1, a 6,000-character line, an emoji, a right-to-left word, and nothing at all. Paste every one into every new form before anyone else does.
