Form Validation Phillip Harrington

The Contact Form checked three fields by hand, and the checking was most of the page. Every form you write from now on needs the same checks: is it there, is it text, is it too long, is it an email address, is it one of the choices. Write them once, in a class, and every form gets them right.

You'll build a small Validator, a registration form that uses it and shows each error beside its field, and a set of PHPUnit tests that prove the validator does what it says. Validation is exactly the kind of code that should have tests: small, fiddly, and the only thing standing between your database and whatever people send.

    src/Validator.php:

    How it works:

  • It's given the data. The constructor takes an array, usually $_POST. It never reaches for $_POST itself, which is what makes it easy to test: hand it any array you like.
  • Each method checks one field and returns it clean, trimmed and typed, or null if it failed. int() returns an actual int, so the rest of your code never sees the string "42".
  • Everything starts with text(). Before anything else, the value has to be a string (not missing, not an array from name[]=), valid UTF-8, and no longer than the limit, counted with mb_strlen() in characters, so "Zoë" is three, not four.
  • Errors are filed by field, so the form can show each one where it belongs. Only the first problem with a field is kept.
  • oneOf() is an allow list, with the strict in_array(), as in Forms.

    The Form

    public/index.php, a registration form that uses it:

    Each field gets its error beside it, and aria-invalid and aria-describedby tie the error to the field, so a screen reader says what's wrong when someone lands on it. What they typed goes back into the form, escaped, so a mistake doesn't mean starting over. The form has novalidate so you can see the server's checks at work; take it off and add required to bring back the browser's as a courtesy.

    docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000 -t public

    Open http://localhost:8000 and press Register with nothing filled in. Then send it nonsense, the way a script would:

    curl -d 'name=&email=alice@&age=12abc&ticket=free' http://localhost:8000

    "Please fix the 4 problems below," and each one beside its field: Name is required, Email must be an email address, Age must be a whole number from 13 to 120, Ticket must be one of the choices.

    Gotchas
  • Validate, then escape. They're different jobs. Validation decides whether to accept a value. Escaping makes a value safe in one particular place: HTML, SQL, a URL. A perfectly valid name can still be <b>Al</b>, and it still gets escaped on the way out.
  • (int) isn't validation. (int) "12abc" is 12, and (int) "banana" is 0. Casting hides bad input; it doesn't refuse it. FILTER_VALIDATE_INT refuses it.
  • Be careful how strict you are about names. People's names have apostrophes, hyphens, spaces, accents, one word or five, and letters from every alphabet. Limit the length and the encoding, and accept the rest.
  • Email validation only checks the shape. alice@example.com passes, whether or not there's an Alice. The only way to know an address works is to send it something and see if they answer.

    • For every check you write, write one test with the input you're afraid of: the array, the 10,000-character string, the invalid UTF-8, the newline. Happy-path tests tell you the code works. Hostile-input tests tell you it can't be fooled, and they keep it that way after the next person edits it.
