View Source Link Phillip Harrington

Your browser's View Source shows the HTML a page sent, never the PHP that made it. The Home Page project ended on that: visitors only see what PHP printed. This project adds a link at the bottom of a page that shows its PHP source, highlighted, for anyone curious how it's made.

It's a small feature with a big trap in it. A page that shows "the file named in the URL" can be asked for any file at all, so most of the work is making sure it shows yours and nothing else.

What You'll Use
  • Query Strings: which file to show, in ?file=.
  • Never Trust Input: the query string is the visitor's, not yours.
  • Arrays: an allow list, as keys and values.
  • Request and Response: a 404 when the answer is no.

    highlight_file() reads a PHP file and prints it as colored HTML, with every < and & escaped, so the code is shown and not run. The interesting part is above it.

    The URL doesn't name a file. It names a key in $allowed, and the real path comes from the array. This may have come up once or twice in the lessons: never trust input. The value of ?file= is whatever the visitor typed, so it never gets anywhere near a path. If it isn't a key in the list, the answer is a 404, and that's the end of it. The is_string() check is there because ?file[]=index.php makes it an array, not a string.

    Run It docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000 -t public

    Open http://localhost:8000 and follow the link. There's the source. The viewer's own link at the bottom shows the viewer, too. Now ask it for something that isn't yours to see:

    curl 'http://localhost:8000/source.php?file=../../../etc/passwd' curl 'http://localhost:8000/source.php?file=/etc/passwd'

    Both get "No source for that." and a 404. Neither one is a key in the list, so neither one is a file as far as this code is concerned.

    New to Docker or the terminal? Tools has the setup.

    Gotchas
  • Never build the path from the URL. The obvious version, highlight_file(__DIR__ . '/' . $_GET['file']), shows your page, and also ../.env, /etc/passwd, and every other file the server can read. That's path traversal, and the Log Viewer project breaks it on purpose. Checking for .. is a deny list, and deny lists miss things. The allow list can't.
  • Showing the source shows everything in it. A password or API key in a file on the list is now on the page. Keep secrets in settings outside public, as in Configuration and the Environment, and never put a settings file on the list.
  • Source isn't the whole story. If a page includes other files, its source shows the require line, not what's in them. Add those to the list too, if you want them seen.

    • php -s index.php prints the same highlighted HTML that highlight_file() does, straight to the terminal. Redirect it to a file and you have colored code to paste into an email or a document, no plugin needed. Just don't leave that file in your web root.
