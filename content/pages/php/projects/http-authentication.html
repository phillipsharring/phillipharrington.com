HTTP Authentication Phillip Harrington

The last few projects built a login the long way: a form, a session, a password hash, a page to change it. HTTP has a login of its own, built into every browser, with no form and no session at all. It's called Basic authentication. It's plain, it's ugly, and it's exactly right for a staff page, a staging site, or a tool only you will use.

You'll build one page behind it: the browser asks for a name and password, PHP checks them against a hash, and only the right pair gets in.

What You'll Use
  • Request and Response: the 401 status and the headers both ways
  • Document Root: the password list lives outside public
  • Passwords: password_hash() and Nothing Else: store a hash, check with password_verify()
  • HTTP, HTTPS and TLS: why this only belongs on HTTPS
    •  Build It

    The conversation goes like this:

    1. The browser asks for the page, with no credentials.
    2. PHP answers 401 Unauthorized, with a WWW-Authenticate: Basic header.
    3. The browser sees that header and shows its own login box. The realm in the header names what you're logging in to.
    4. It asks again, this time with an Authorization header: the word Basic, then name:password in base64.
    5. PHP decodes it into $_SERVER['PHP_AUTH_USER'] and $_SERVER['PHP_AUTH_PW'], and your code checks them.
    6. The browser remembers the pair and sends it with every request to that site.
    Step 1: The Users

    Make a project folder, and in it, users.php: each user name and a hash of its password. Never the password itself.

    That hash is for correct horse battery staple. To make your own, this script reads a password from the keyboard, so it doesn't end up in your shell history:

    docker run --rm -it -v "$PWD":/app -w /app php:8.4-cli php hash-password.php Step 2: The Check

    auth.php holds one function. It reads the name and password PHP decoded, and either returns the name or answers 401 and stops.

    Never trust input. The Authorization header is whatever the client sent, so the name might be empty, absurdly long, or made of anything. It only ever gets used as an array key and checked against a hash, so none of that matters here. Notice the dummy hash: an unknown name still costs one password_verify(), so a wrong name and a wrong password take the same time, and the timing can't tell anyone which names exist.

    Step 3: The Page

    Then public/index.php, the page behind the door:

    Start it, with public as the web root:

    docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000 -t public

    Open http://localhost:8000. The browser asks for a name and password. Cancel, and you get the 401's text. Log in as editor, and you're in.

    Step 4: Watch It with curl curl -i http://localhost:8000 curl -v -u 'editor:correct horse battery staple' http://localhost:8000 Only the new parts: Sign in with this user name and password, using HTTP's Basic authentication. The quotes keep the spaces in the password.

    The first gets the 401 and its WWW-Authenticate header. The second shows, in curl's > lines, exactly what went out:

    > Authorization: Basic ZWRpdG9yOmNvcnJlY3QgaG9yc2UgYmF0dGVyeSBzdGFwbGU=

    Decode it:

    echo 'ZWRpdG9yOmNvcnJlY3QgaG9yc2UgYmF0dGVyeSBzdGFwbGU=' | base64 -d Print the text in the quotes. Hand that text to base64, which decodes it (-d) back to the original bytes.

    There's the password. Base64 is a way to write bytes as plain letters, not a lock. Anyone who sees the request sees the password, on every request, which is why Basic authentication only ever goes over HTTPS.

    Basic authentication was already in the HTTP/1.0 specification, RFC 1945, published in 1996. It has barely changed since. Its current spec, RFC 7617, mostly adds a way to say the password is UTF-8: the charset="UTF-8" in the example's header. Gotchas
  • Without HTTPS, it's a password on a postcard. Every request carries it, readable by anything in between. On a live site, HTTPS or nothing.
  • There's no logout. The browser keeps sending the pair until you close it. If people need to log out, or you need to lock someone out mid-session, use the form and session login from the earlier projects.
  • Nothing stops guessing. The browser box will retry forever. A real one needs a limit on failures, like the one in Rate Limiting.
  • Some setups hide the header from PHP. PHP's built-in server passes it along. Apache running PHP as CGI or FastCGI normally keeps Authorization to itself, and PHP_AUTH_USER is just missing. The fix lives in the server's settings (CGIPassAuth On, in Apache), not in your code.
  • Your web server can do this without PHP. nginx and Apache both protect a folder with Basic authentication on their own. Doing it in PHP is for when the check depends on something only your app knows.

    • Put Basic authentication in front of every staging and preview site, even the ones nobody knows about. Search engines find them anyway, and an unlocked copy of your site with test data and debug output turned on is the one you don't want indexed. One password in the web server's config, and it's done.
