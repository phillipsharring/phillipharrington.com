Return Early Phillip Harrington

Defensive Programming checked its arguments at the top of the function and threw if they were wrong. That shape works for more than errors. Any case that ends a function early, "not logged in," "nothing to do," can be handled first and sent on its way, leaving the real work at the bottom with nothing wrapped around it.

What's Returning Early?

Writing a function as a list of checks, each with its own answer, followed by the main path. Each check is a guard clause: if this, return that. Once you're past it, you never think about it again.

The Arrow

The other way is to nest: if this is fine, then if that's fine, then if the next thing is fine, do the work. Each condition pushes the code further right, and each answer for "not fine" ends up in an else far below the if it belongs to. The shape on screen is an arrowhead pointing right, and people call it arrow code.

Martin Fowler's Refactoring, first published in 1999, gave this change a name: "Replace Nested Conditional with Guard Clauses." Naming refactorings was the point of the book. "Extract Method" and "Rename Method" are in there too, which is where your editor's menu got them. How It Works
  1. Find the cases that stop the function: missing, invalid, not allowed, empty.
  2. For each, write the condition the way it fails (if ($user === null), not if ($user !== null)), and return or throw right there.
  3. Put them in order: the ones that make the later checks possible go first.
  4. Write the main work last, at one level of indent, knowing every check above has passed.

The reader reads it the same way it runs: top to bottom, one condition at a time, each answer next to its question.

In PHP
  • return in a function, and throw for the cases that are errors.
  • continue in a loop: skip this item and go on to the next, like the unknown status in Magic Numbers in Code. break to leave the loop.
  • exit in a script that has answered: after a redirect, a 404, a 422 for bad input, as shop.php did in Defensive Programming.
  • ?? and ?-> handle some "missing" cases in a single expression, with no if at all.
    • Gotchas
  • header('Location: ...') doesn't stop the script. It sets a header, and PHP carries on running the rest of the page, including whatever the redirect was meant to protect. Follow it with exit.
  • A return in the middle can skip cleanup. If the function opened a file or started a transaction, an early return can leave it open. Do the checks before you open anything, or use try/finally. The next lesson has another way.
  • Returns buried in the middle aren't guard clauses. Guards go at the top, where a reader looks for them. A return deep inside a loop inside an if is just hard to find.
  • The order of the guards matters. Check that the user exists before you check whether they're verified, or the second check reads a property of null.

    • When you see if (ok) { thirty lines } else { one line }, flip the condition, put the one line first with a return, and drop the else. The thirty lines move left a level, and the short answer sits next to its question.

    Returning early has a famous rival: the rule that a function should have exactly one return, at the end. They get along better than you'd think. Next: single point of return.
