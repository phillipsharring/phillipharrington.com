Functions Phillip Harrington

You've been calling PHP's functions since the first lesson: strlen(), htmlspecialchars(), array_map(). Writing your own is how you stop repeating yourself, and how you give a piece of work a name. Scope already showed the most important rule: a function sees only what you hand it. This lesson is the rest of the line that starts with function.

What's a Function?

A named piece of code that takes values in and hands one back:

function format_cents(int $cents): string { return '$' . number_format($cents / 100, 2); }
  • format_cents is the name. You call it with format_cents(1999).
  • (int $cents) is the parameter list: what goes in, each with a type and a name.
  • : string is the return type: what comes out.
  • return hands the value back and ends the function, right there.
    •  Parameters
  • Defaults: string $greeting = 'Hello' can be left off when calling. Put parameters with defaults after the ones without.
  • Named arguments: greet(name: 'Carol', greeting: 'Hi') says which value is which, in any order. Since PHP 8.0.
  • Any number: int ...$prices collects every remaining argument into an array.
  • Copies: each parameter is a copy of what was passed. Changing it inside doesn't change the caller's variable.
    • Return Types
  • ?int: an int, or null. Useful for "here's the answer, or there isn't one."
  • void: returns nothing. It does something instead, like writing a log line.
  • never: never returns at all, because it always stops the script or throws.
    • Functions as Values

    A function can be handed to another function. strlen(...), with three dots, is strlen itself, not a call to it, so array_map(strlen(...), $words) runs it on every word. An arrow function, fn(int $c): int => $c * 2, is a small one written right where it's needed.

    Reusable pieces of program are older than programming languages. On Cambridge's EDSAC, one of the first stored-program computers, David Wheeler worked out how to jump into a shared piece of code and come back to where you left off; it was called the Wheeler jump, and it's the subroutine. A few years later, in 1952, Grace Hopper's A-0 system built programs by pulling numbered subroutines from a library and stitching them together, which is why it's often called the first compiler. How It Works

    When your code calls format_cents(1999):

    1. PHP finds the function. It can be defined anywhere in the file, even below the call.
    2. It checks each argument against the parameter's type: under strict_types, it must match exactly, or it's a TypeError.
    3. It fills in defaults for anything left off.
    4. It runs the body in a fresh scope, with the parameters as its variables.
    5. At return, it checks the value against the return type, and hands it back. The call is replaced by that value, so echo format_cents(1999); prints $19.99.

    The best functions are the ones where that's the whole story: values in, one value out, nothing else touched. You can read them on their own, test them on their own, and trust them anywhere. Some functions have to change something, like writing a file or sending an email. Keep those separate, and keep them small.

    Try It

    A handful of functions, and one call that breaks the rules. In a folder, make functions.php:

    docker run --rm -v "$PWD":/app -w /app php:8.4-cli php functions.php

    Each line of output comes from one call. quantity_from() is the pattern for input: never trust input, so it checks the type and the range, and gives back a clean int or null. '3' passes; '30', 'three' and an array don't. The code that calls it only has to check for null.

    The last line passes the string '1999' to format_cents(), and strict_types stops it with a TypeError that names the function, the parameter, and both lines involved.

    In PHP
  • function name(type $param): type { ... }: the shape of every function.
  • return: hand back a value and stop.
  • ?type, void, never, mixed, and unions like int|string, from Types of Types.
  • name: value when calling, for named arguments.
  • ...$rest: any number of arguments, as an array.
  • strlen(...): a function as a value. fn() => ...: a small one on the spot.
  • function_exists('name'): is it defined?
    •  Gotchas
  • A function with no return returns null. Forget the return, and the caller gets null. A return type catches that: : string with no return is a TypeError.
  • Booleans in a row are unreadable. make_user('Alice', true, false, true) means nothing to the next reader. Use named arguments, or split it into separate functions.
  • An & in front of a parameter changes the caller's variable. function add_tax(int &$cents) works on the original, not a copy. PHP's own sort() does this. Don't, in your own functions: return the new value instead.
  • You can't define the same name twice. Including a file of functions twice is a fatal error, "Cannot redeclare." Includes has the fix.
  • Names are case-insensitive. Format_Cents() calls format_cents(). Variables aren't. Write a name the same way every time.

    • Named arguments fix PHP's own functions too. htmlspecialchars($text, double_encode: false) skips the two arguments you don't care about, and the call says what it does. The names are the parameter names in the manual's signature, so Documentation is where you find them.

    When a function gets something it can't handle, PHP tells you: a warning, a TypeError, a fatal error. Where those messages go, and where they must never go, is next: Errors and the Error Log.
