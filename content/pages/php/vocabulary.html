Web Nerdism w/ PHP 101 › Reference

Vocabulary Phillip Harrington

The web words the course uses, each in a sentence or two, with the lesson that explains it. In a lesson, a word in italics with a dotted underline is one of these: the first time a page uses it, it links here.

A Abstract Class

A class that can't be made with new and exists to be extended. It can hold finished methods and abstract ones, which each child class has to write. Explained in Abstract Classes.

Access Log

A file the web server writes with one line per request: who asked, when, for what, and the status code it got. Explained in Access and Error Logs.

ACID

Atomic, Consistent, Isolated, Durable: the four promises a database makes about a transaction. Explained in Transactions.

AJAX

A page talking to the server in the background and updating itself, without loading a new page. Short for Asynchronous JavaScript and XML, though today it's mostly JSON. Explained in fetch() and AJAX.

API

Application Programming Interface: the way one program offers to be used by another. On the web, usually a set of URLs that take requests and answer in JSON. Explained in REST.

API Key

A long secret string a service gives you, sent with each request to prove the request is yours. Anyone who has it can act as your app. Explained in Secrets Out of Code.

Argument

The value you pass in when you call a function, filling one of its parameters. Explained in Functions.

Array

An ordered collection of values, each stored under a key. In PHP one works as a list (keys 0, 1, 2) or with named keys. Explained in Arrays.

ASCII

The 1963 American list of 128 characters, one byte each: English letters, digits, punctuation. UTF-8 keeps it unchanged. Explained in Text and UTF-8.

Attribute

A name="value" pair inside an HTML opening tag, like href on a link. Explained in HTML.

Authentication

Checking who someone is, usually with a username and password. Explained in HTTP Authentication.

Autoloading

PHP calling a function you registered the first time code uses a class it hasn't loaded yet, so that function can find the class's file and load it. Explained in Autoloading with Composer and PSR-4.

B Body

The content of a request or response, after the headers and a blank line: the HTML of a page, a form's fields, some JSON. Explained in Request and Response.

Boolean

A type with two values, true and false. PHP calls it bool. Explained in Types of Types.

Browser

The program people use to visit the web: a client that sends requests, then shows the HTML it gets back. Explained in Client/Server.

Byte

Eight bits: one number from 0 to 255, the unit files, strings and network traffic are measured in. One character can take more than one. Explained in Text and UTF-8.

C Cache

A copy of an answer, kept somewhere closer or cheaper than where the answer comes from, so it doesn't have to be made again. Browsers, CDNs and your own app all keep them. Explained in Caching.

Cache Invalidation

Throwing a cached copy away because the real answer has changed: let it expire, delete it on change, or change its name. Explained in Caching.

Cascade

The CSS rules for which style wins when two rules set the same property: the more specific selector, then the later rule, with some properties inherited from the parent. Explained in CSS.

CDN

Content delivery network: servers all over the world that keep copies of your files and pages and answer from the one nearest the visitor. Explained in What's in the Middle.

Certificate

A server's ID card for HTTPS, vouched for by a certificate authority the browser trusts. It proves the server is the one the name says. Explained in HTTP, HTTPS and TLS.

Character Set

A list that gives every character a number, and with it the rules for turning bytes into letters. The charset in a Content-Type header says which one the bytes use. Explained in Content Types and Text and UTF-8.

Class

A blueprint for a kind of thing: the properties each one has and the methods that work on them. Explained in Classes and Objects.

Clickjacking

Loading your page, invisible, in a frame over an attacker's page, so a visitor's click lands on your button without them knowing. Explained in Security Headers.

Client

The program that connects to a server and asks for something: a browser, curl, a phone app, another server. Explained in Client/Server.

Closure

A function without a name, kept in a variable or passed along, that can borrow variables from where it was made. Explained in Scope.

CMS

Content management system: pages stored in a database, which people edit through an admin form instead of changing code. Explained in Content Management System.

Coding Standard

A written set of rules for how code looks: indentation, braces, spacing, naming. PHP's are the PSRs. Explained in Coding Standards.

Collation

A database's rules for comparing and sorting text: whether case and accents count, and what comes first. Explained in Character Sets and Collation.

Column

One kind of fact in a database table, with a name and a type, like email or created_at. Explained in SQL.

Command Line

Working by typing commands into a terminal instead of clicking, and the line you type them on. Explained in Tools.

Constant

A name for a value that can't change while the program runs. Explained in Constants, Static Variables and Functions.

Container

A small sealed box, run by Docker, with exactly the software one project needs, kept apart from the rest of your computer. Explained in Tools.

Content Type

A type/subtype label, like text/html or application/json, that says what the bytes in a body are. Sent in the Content-Type header. Explained in Content Types.

Controller

In MVC, the part that handles a request: it reads the input, asks the model for what's needed, picks a view, and returns the response. Explained in MVC.

Cookie

A small name and value a browser keeps for one site. The server sets it with a Set-Cookie header, and the browser sends it back with every request to that site. Explained in Cookies.

CORS

Cross-Origin Resource Sharing: response headers a server sends to say a page from another origin may read its answers. Explained in CORS.

Cron

The program that runs commands on a schedule. Each scheduled command is a cron job, written as one line in a crontab. Explained in Cron Jobs.

CRUD

Create, Read, Update, Delete: the four things most apps do to their data, matching SQL's INSERT, SELECT, UPDATE and DELETE. Explained in CRUD.

CSRF

Cross-site request forgery: another site makes a visitor's own browser send your site a request they never meant to send, with their real cookies attached. Explained in CSRF.

CSRF Token

A long random secret kept in the session and put in a hidden field in every form. The server refuses any form that doesn't send it back. Explained in CSRF.

CSS

Cascading Style Sheets: a list of rules, each a selector and some properties, that says how a page looks. Explained in CSS.

CSV

Comma-separated values: a table as plain text, one line per row, commas between the fields. Explained in CSV.

D Database

A separate server that stores your data, finds any piece of it fast, and lets many requests read and write at once. Explained in Working with a Database: PDO and Prepared Statements.

Defensive Programming

Checking your assumptions in code, at the top of a function, before you rely on them, and failing loudly when they're wrong. Explained in Defensive Programming.

Dependency

Anything your code needs from outside itself to do its job: another object, or a package someone else wrote and maintains. Explained in Dependency Injection and Your Dependencies Are Your Code Too.

Dependency Injection

Giving an object what it needs, usually through its constructor, instead of letting it go and get it. Explained in Dependency Injection.

DNS

The Domain Name System: how a name like example.com turns into an IP address a client can connect to. Explained in DNS.

DNS Record

One fact about a domain name, such as its address (A, AAAA), an alias (CNAME) or where its mail goes (MX). Explained in DNS.

Document Root

The one folder a web server hands out. Anything inside it can be requested by URL; anything outside it can't. Explained in Document Root.

DOM

Document Object Model: the tree of elements a browser builds from a page's HTML, which JavaScript reads and changes. Explained in HTML and JavaScript.

Domain Name

The name people type instead of an IP address, like example.com, read right to left from the most general part. Explained in DNS.

DRY

Don't Repeat Yourself: each piece of knowledge, a rule, a limit, a formula, lives in exactly one place in the code. Explained in DRY.

E Element

One piece of an HTML page: an opening tag, its content and a closing tag, like <p>...</p>. Explained in HTML.

Encoding

Writing data in an agreed format so it survives the trip: characters as bytes (UTF-8), or unsafe characters in a URL as % and two hex digits. Explained in Anatomy of a URL and Text and UTF-8.

Encryption

Scrambling data so only someone with the key can read it. Unlike a hash, it's two-way: with the key, you get the original back. Explained in HTTP, HTTPS and TLS.

Endpoint

One URL on a server that code calls to get or change something, usually answering in JSON. Explained in fetch() and AJAX.

Enum

A type with a fixed list of values, like the statuses an order can have. Explained in Modern PHP.

Environment Variable

A named value every program gets from whatever started it, used for settings and secrets that change from one machine to the next. Explained in Configuration and the Environment.

Error Log

A file of things that went wrong, each with a time and a level. The web server keeps one and PHP keeps another. Explained in Access and Error Logs.

Escaping

Writing a character so it means itself instead of its job: &lt; for < in HTML, so input shows as text instead of becoming a tag. Explained in XSS and Escaping Output.

Event

Something that happens that code can react to: a click or a key in the browser, or in your app, a thing like "an order was placed" handed to whoever is listening. Explained in JavaScript and Observers.

Exception

An object describing what went wrong, which code throws. It climbs out of each function until something catches it, or the program stops. Explained in Exceptions and Try/Catch.

F Factory

A class whose method makes and returns a new object, so the caller gets one without knowing which class it is or how it's set up. Explained in Factories.

FastCGI

The protocol a web server uses to hand a request to PHP-FPM and get the answer back. Explained in How PHP Actually Runs: nginx and PHP-FPM.

Firewall

Something in front of your app that blocks traffic it doesn't like. A web application firewall reads each request and blocks the ones that look like attacks. Explained in What's in the Middle.

Float

A number with a fractional part, like 2.5. Stored in binary, so it's approximate: never use one for money. Explained in Types of Types.

Foreign Key

A column that holds another table's primary key, plus a rule that the row it points to must exist. Explained in Relating Tables: Keys and Foreign Keys.

Form

The part of an HTML page with fields to fill in and a button, which the browser sends to the server as a request. Explained in Forms.

Fragment

The part of a URL after a #: the name of a spot on the page. The browser keeps it and never sends it to the server. Explained in Anatomy of a URL.

Front Controller

One PHP file, usually public/index.php, that every request goes to, whatever its URL. Explained in Single Point of Entry.

Function

A named piece of code that takes values in and hands one back, so you can write it once and call it anywhere. Explained in Functions.

G Guard Clause

A check at the top of a function that returns or throws right away when something's wrong, so the rest of the function doesn't have to. Explained in Return Early.

H Hash

The fixed-length string a one-way function makes from some data. The same input always gives the same hash, and there's no way back to the input. Explained in Passwords: password_hash() and Nothing Else.

Header

A Name: value line at the top of a request, a response or an email, carrying facts about the message rather than the message itself. Explained in Request and Response.

Host

A computer on a network, another word for a server. In a URL, the host is the part that says which server: a name or an address. Explained in Client/Server and Anatomy of a URL.

HSTS

HTTP Strict Transport Security: a header that tells the browser to reach this site only over HTTPS from now on. Explained in Security Headers.

HTML

HyperText Markup Language: plain text with tags that say what each part of a page is. Explained in HTML.

HTTP

HyperText Transfer Protocol: the rules for one exchange on the web, a request and then a response. Each request stands on its own. Explained in HTTP, HTTPS and TLS.

HTTP Method

The verb at the start of a request that says what the client wants done: GET, POST, PUT, PATCH, DELETE. Explained in Request and Response.

HTTPS

The same HTTP, sent through an encrypted TLS connection. Explained in HTTP, HTTPS and TLS.

I Idempotent

Safe to repeat: sending the request twice leaves things the same as sending it once. GET, PUT and DELETE are; POST isn't. Explained in REST.

Index

A sorted copy of one or more columns, pointing back to each row, so the database can find rows without reading the whole table. Explained in Indexes.

Integer

A whole number, like 42 or -7, stored exactly. PHP calls it int. Explained in Types of Types.

Interface

A named list of public methods with no code in them. A class that implements it promises to have every one, and PHP checks. Explained in Interfaces.

IP Address

The number a computer is reached at on a network, like a phone number: 93.184.215.14 in IPv4, a longer one in IPv6. Explained in DNS.

J JavaScript

The programming language built into every browser. It runs on the visitor's computer, so the visitor controls it. Explained in JavaScript.

Join

Combining rows from two tables in one query, matched on a column they share. Explained in Selecting Data.

JSON

JavaScript Object Notation: data written the way JavaScript writes it, with a few strict rules. The usual format for APIs. Explained in JSON.

L Load Balancer

A server that spreads requests across several app servers and stops sending to any that aren't healthy. Explained in What's in the Middle.

localhost

The name every computer uses for itself, address 127.0.0.1. Explained in Client/Server.

Lock File

A file, like composer.lock, that records exactly which version of every package was installed, so every machine gets the same code. Explained in Your Dependencies Are Your Code Too.

M Magic Number

A literal value in code, like 86400, whose meaning isn't written anywhere in the code. Explained in Magic Numbers in Code.

Method

A function that belongs to a class, called on an object. Explained in Classes and Objects.

Middleware

A small piece of code that gets the request and the next thing in line. It can act before and after passing it on, or answer by itself. Explained in Middleware and Pipelines.

Migration

One change to the database's structure, written in a file and applied in order by a runner that remembers which ones it has run. Explained in Migrations.

MIME Type

Another name for a content type, also called a media type. MIME is Multipurpose Internet Mail Extensions, where the labels started. Explained in Content Types.

MVC

Model, View, Controller: splitting an app into its data and rules, what goes back to the visitor, and the code that handles each request and connects the two. Explained in MVC.

N N+1 Query

One query for a list, then one more query for each of its N rows, usually inside a loop. The fix is to ask once, with a join. Explained in Selecting Data.

Namespace

A family name for classes, like App\Mail, so yours don't collide with everyone else's. Explained in Autoloading with Composer and PSR-4.

Normalization

Arranging tables so every fact is stored in exactly one place. Explained in Normalization.

Null

No value at all, which is different from zero or an empty string. Explained in Types of Types.

O Object

One thing built from a class with new, with its own values for the class's properties. Explained in Classes and Objects.

Observer

Code that has asked to be told when something happens, so it can react. Also called a listener or subscriber. Explained in Observers.

Operator

A symbol that takes one or two values and gives back a new one, like +, === or &&. Explained in Operators.

Origin

The scheme, host and port of a URL together, like https://example.com:443. The path doesn't count. Explained in CSRF and CORS.

P Package Manager

A program that installs, updates and removes software with one command each, like Homebrew, apt or Composer. Explained in Tools.

Parameter

A name in a function's definition for a value it takes in. The value passed for it is the argument. Explained in Functions.

Path

Where something is. In a URL, the part after the host that says which thing on that server; on disk, the folders down to a file. Explained in Anatomy of a URL and Includes.

PCI DSS

The Payment Card Industry Data Security Standard: the rules for anyone who stores, processes or transmits card numbers. Explained in Don't Touch Cards.

Permissions

The settings on every file that say who owns it and who can read, write or run it. PHP runs as a user, and gets only what that user is allowed. Explained in Working with Files.

Pipeline

A line of middleware with a handler at the end. The request goes in through each layer and the response comes back out through them in reverse. Explained in Middleware and Pipelines.

Port

A number that picks which door on a server to knock on: 80 for HTTP, 443 for HTTPS. Explained in Anatomy of a URL.

Preflight

An OPTIONS request the browser sends first, asking a server on another origin whether the real request is allowed. Explained in CORS.

Prepared Statement

A query with placeholders in it, sent to the database first, with the values sent separately, so a value can only ever be a value and never more SQL. Explained in Working with a Database: PDO and Prepared Statements and SQL Injection.

Primary Key

The column that tells one row from every other. It never repeats, is never NULL, and shouldn't change. Explained in Relating Tables: Keys and Foreign Keys.

Production

The live site, with real visitors and real data, as opposed to the copy you develop on. Explained in Configuration and the Environment.

Property

A variable that belongs to an object, declared in its class. Explained in Classes and Objects.

Protocol

The agreed rules for how two computers talk: who speaks first, what each message looks like, what the answers mean. HTTP is one. Explained in Client/Server.

Q Query

A request to a database, written in SQL, to get data or change it. Explained in SQL.

Query String

The part of a URL after a ?: name=value pairs, joined with &, that give the server extra instructions. Explained in Query Strings.

Queue

A list of jobs to do later. The page writes the job down and answers at once; a separate worker takes jobs off the list, does them, and retries the ones that fail. Explained in Queues.

R Rate Limiting

A cap on how often something can happen in a stretch of time, like five logins a minute. Over it, the server answers 429 Too Many Requests. Explained in Rate Limiting.

Redirect

A response that sends the browser somewhere else: a 3xx status code and a Location header with the new URL. Explained in Request and Response.

Request

What a client sends a server: a method, a URL, headers, and sometimes a body. Explained in Request and Response.

Response

What the server sends back: a status code, headers, and usually a body. Explained in Request and Response.

REST

Representational State Transfer: designing an API around the web's own parts. URLs name things, methods say what to do with them, status codes say how it went. Explained in REST.

Reverse Proxy

A server in front of your app that takes every request, passes it along, and passes the answer back. Explained in What's in the Middle.

Route

One entry in the list that maps a URL, like /account, to the code that handles it. Explained in Single Point of Entry.

Row

One thing in a database table, like one user or one order, with a value for each column. Explained in SQL.

S Salt

Random bytes, different for every password, mixed in before hashing and stored next to the hash, so two people with the same password get different hashes. Explained in Passwords: password_hash() and Nothing Else.

Same-Origin Policy

The browser's rule that a page's JavaScript can read answers only from its own origin, unless the other server says otherwise with CORS. Explained in CORS.

Schema

The structure of a database: its tables, their columns and types, and the rules on them. Explained in Creating Tables.

Scheme

The first part of a URL, before the ://, that says which protocol to use: http, https, mailto. Explained in Anatomy of a URL.

Scope

The part of your code where a variable can be seen. A variable made inside a function exists only inside it. Explained in Scope.

Security Advisory

A published notice that some versions of a package have a known security hole, and which version fixes it. Explained in Your Dependencies Are Your Code Too.

Selector

The part of a CSS rule that picks which elements it applies to, like p or .warning. Explained in CSS.

Separation of Concerns

Keeping each kind of job your code does, like reading input, deciding and showing, in its own function, file or class. Explained in Separating Concerns.

Server

A program that listens on a port and answers requests, and the computer it runs on. Explained in Client/Server.

Session

A way to remember a visitor between requests: a cookie holding a long random id, and data kept on the server under that id. Explained in Sessions.

Session Fixation

An attack where someone picks a session id, gets a victim's browser to use it, and waits for them to log in. The fix is a new id at login. Explained in Sessions and Cookie Flags.

Side Effect

Anything code does beyond handing back a value: output, a file written, a cookie set, an email sent, a global changed. Explained in Declaring Symbols vs. Causing Changes.

Singleton

A class that makes sure there's only ever one of itself, handed out by a static method. Explained in Singletons.

Slug

The short, readable, URL-safe name of a page or post, like my-first-post, used in its address. Explained in Content Management System.

SMTP

Simple Mail Transfer Protocol: the protocol mail servers use to send email and pass it along. Explained in Sending Email.

Soft Delete

Marking a row as deleted, often with a deleted_at column, instead of removing it. Every query then has to leave those rows out. Explained in Deleting Data.

SQL

A language for asking a database for data and for changing it. You say what you want, and the database works out how. Explained in SQL.

SQL Injection

Input glued into a string of SQL, where a quote in it ends your SQL and what follows is SQL the visitor wrote. Explained in SQL Injection.

Status Code

The three-digit number at the top of a response that says how it went: 2xx worked, 3xx look elsewhere, 4xx the client's mistake, 5xx the server's. Explained in Request and Response.

String

A row of bytes, usually text. Explained in Strings.

Subdomain

A name to the left of a domain, like www or shop in shop.example.com, chosen by the domain's owner. Explained in Anatomy of a URL.

Superglobal

A variable PHP fills in for you that can be seen everywhere, like $_GET, $_POST and $_SERVER. Explained in Scope.

T Table

A grid in a database: each column is one kind of fact, each row is one thing. Explained in SQL.

Terminal

A window where you type commands instead of clicking. Explained in Tools.

Test Harness

Code whose only job is to run other code and check what it does. Explained in Two-Dollar Test Harnesses.

TLS

Transport Layer Security: what puts the S in HTTPS. It encrypts the connection and uses a certificate to prove the server is who it says. Its old name was SSL. Explained in HTTP, HTTPS and TLS.

Transaction

A group of database statements treated as one: either all of them happen, or none of them do. Explained in Transactions.

TTL

Time to live: how many seconds a copy of an answer, like a DNS record or a cached page, may be kept before asking again. Explained in DNS.

Type

The kind of value something is: a string, an integer, an array. In PHP the type belongs to the value, not the variable. Explained in Variables, Types and strict_types.

Type Juggling

PHP converting a value to another type to fit an operation, so '5' + 5 is 10. Explained in Variables, Types and strict_types.

U Unicode

One list of characters for every writing system, each with its own number, called a code point. Explained in Text and UTF-8.

Unit Test

A test that checks one small piece of code on its own, with nothing else running. Explained in Testing.

Upsert

An insert that turns into an update when the row is already there. Explained in Inserting Data.

URL

Uniform Resource Locator: a web address. It tells a client which protocol to use, which server, which port, and what to ask for. Explained in Anatomy of a URL.

UTF-8

The web's character encoding: one to four bytes per character, with ASCII unchanged. Use it everywhere. Explained in Text and UTF-8.

V Validation

Deciding whether to accept a value: is it there, is it the right shape, is it in range. Explained in Naming Things and built in Form Validation.

Variable

A name for a value. In PHP it starts with $ and comes into being when you assign to it. Explained in Variables, Types and strict_types.

W Web Root

Another name for the document root, usually a public/ folder inside the project. Explained in Document Root.

Web Server

A server that speaks HTTP: it takes requests for URLs and answers with files or with what a program like PHP makes. nginx, Apache and Caddy are web servers. Explained in Client/Server.

Web Shell

A small script, often slipped in through a file upload, that runs whatever command it's sent and sends back the result. Explained in File Uploads.

Webhook

A request one server sends another when something happens, like a POST saying a payment went through, usually signed so the receiver can check who sent it. Explained in Don't Touch Cards and Taking a Payment with Stripe Checkout.

X XSS

Cross-site scripting: a page prints input that contains HTML, and the browser runs the script in it as if it were yours. Explained in XSS and Escaping Output.
