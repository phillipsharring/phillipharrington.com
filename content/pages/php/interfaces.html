Interfaces Phillip Harrington

An abstract class shares code. Sometimes there's no code to share, only an agreement. The code that sends a reminder doesn't care whether it goes by email, by text, or onto the screen while you're testing. It cares that whatever it's handed can send. An interface is that agreement, written down where PHP can check it.

What's an Interface?

A named list of public methods, with their signatures and no bodies. A class that says implements Notifier promises to have every method on the list, and PHP holds it to that.

Then a function can ask for a Notifier instead of a particular class. Any object whose class implements it will do, including classes written years later.

Interface or Abstract Class?
  • An interface has no code and no properties. A class can implement as many as it likes.
  • An abstract class can have both. A class can extend only one.
    •

    When you only need to say what something can do, use an interface. Most of the time, that's all you need.

    How It Works
    1. When PHP loads a class that implements an interface, it checks every method is there, with a compatible signature. If one is missing, the class doesn't load.
    2. A function that declares Notifier $notifier gets checked on every call: is this object's class one that implements Notifier?
    3. If it is, the function calls $notifier->send(), and whichever class it is runs its own send().
    4. If it isn't, PHP throws a TypeError before the function starts.

    The check in step two is by name, not by shape. A class with exactly the right methods that never says implements doesn't count.

    In PHP
  • interface Notifier { ... } declares one. Every method in it is public.
  • class ScreenNotifier implements Notifier keeps the promise; implements Notifier, Countable keeps two.
  • interface Alerts extends Notifier: an interface can build on others.
  • $x instanceof Notifier asks whether an object keeps the promise.
  • PHP's own interfaces plug your objects into the language: Countable for count(), IteratorAggregate for foreach, JsonSerializable for json_encode(), Stringable for anything with a __toString().
  • Interfaces can hold constants, too: Notifier::MAX_LENGTH.
    •  Gotchas
  • An interface checks names and types, not behavior. A send() that does nothing keeps the promise as far as PHP knows. What it actually does is for your tests, at the end of this section.
  • Adding a method breaks every class that implements it. Each one is now missing a method. Keep interfaces small, so they rarely need to change.
  • One class, one interface, no reason. An interface with exactly one class behind it, and no second one coming, is just another file to open. Add the interface when the second kind shows up, or when a test needs a stand-in.
    • In the early 1800s, every machine shop cut screw threads its own way, so a bolt from one shop rarely fit a nut from another. In 1841, the English engineer Joseph Whitworth proposed one standard: a fixed thread angle, and a fixed number of threads per inch for each size. Once a bolt promised to be Whitworth, any Whitworth nut would do. That's an interface.

    Write the interface for the code that uses it, not the class that implements it. remindAll() needs send(), so Notifier has send(), and nothing about SMTP servers or retries. The smaller it is, the easier it is to write a second one, a fake one for tests included.
