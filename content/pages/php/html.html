HTML Phillip Harrington

Most of what PHP sends is HTML. You've written bits of it in every Try It since Forms, and escaped what went into it since XSS and Escaping Output. This section steps back to the technologies around PHP, starting with the one every page is made of: what HTML is, what a whole page needs, and how to build one from PHP without letting input rewrite it.

What's HTML?

HyperText Markup Language: plain text, with tags that say what each part of it is. The browser reads the tags and draws the page.

Elements and Attributes <a href="/shirts" class="big">Shirts</a>

That's one element: an opening tag, <a>, the content, Shirts, and a closing tag, </a>. Elements go inside other elements, like a list inside a section inside the body. The name="value" pairs in the opening tag are attributes: href says where the link goes, and class gives CSS something to grab. A few elements, like <img> and <input>, have no content and no closing tag.

The Document

Every page needs the same few things around its content:

  • <!doctype html> first, so the browser follows the modern rules, not the old ones it keeps for pages from the 1990s.
  • <html lang="en">, which says what language the page is in. Screen readers use it to pick a voice, and browsers to offer translation.
  • <meta charset="utf-8">, early in the <head>, so the browser reads the bytes as UTF-8. The Text and UTF-8 lesson is why that matters.
  • <meta name="viewport" ...>, so phones show the page at their own width instead of shrinking a desktop page to fit.
  • A <title>, for the tab, bookmarks and search results.
    •  Elements That Mean Something

    Pick elements for what things are, not how they look: <h1> to <h6> for headings, in order; <p> for paragraphs; <ul> and <li> for lists; <a> to go somewhere and <button> to do something; <header>, <main>, <nav> and <footer> for the parts of a page. Screen readers, search engines and the browser's reader mode all depend on it. How it looks is CSS's job.

    In 1991, Tim Berners-Lee described the first HTML in a short document called "HTML Tags." Many of the elements in it, like <a>, <p>, the headings and the lists, are still in every page today. HTML is now a "living standard," updated continuously by the browser makers' group WHATWG, rather than numbered versions. How It Works
    1. The browser gets the response, sees text/html from Content Types, and starts reading at the top.
    2. It turns the tags into a tree of elements, called the DOM: the html element, with the head and body inside, and everything else inside those.
    3. Along the way it finds the stylesheets, scripts and images the page names, and sends a request for each one.
    4. It draws the tree, styled by the CSS.

    Browsers forgive almost anything. A missing closing tag, a list item outside a list: they guess what you meant and draw something. That's kind to visitors and hard on you, because broken HTML can look fine until it doesn't.

    When PHP builds HTML, a value from outside is just more text in that stream, and the browser can't tell your tags from tags inside a visitor's name. Never trust input: every value goes through htmlspecialchars() on the way into the page.

    Try It

    A whole page, built by PHP. In a folder, make index.php:

    Start it:

    docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000

    Open http://localhost:8000, then view the page source (Ctrl+U, or Cmd+Option+U on a Mac). That's what PHP sent: no PHP left in it, just HTML. Click the link to say hello to Alice. Then send a name with tags in it:

    curl 'http://localhost:8000/?name=%3Cem%3EAlice%3C/em%3E'

    The name comes back as &lt;em&gt;Alice&lt;/em&gt;. In the browser that shows as the text <em>Alice</em>, angle brackets and all, not as Alice in italics. The visitor gets to choose the words, never the tags.

    In PHP
  • Text outside <?php ?> is sent as it is, so a page can be mostly HTML with PHP only where it's needed.
  • <?= htmlspecialchars($value) ?> for every value you didn't write yourself, in text and in attributes alike. Since PHP 8.1 it escapes both kinds of quotes by default, so attributes in either quotes are safe.
  • if (...): and foreach (...):, with endif; and endforeach;, read better than braces between lines of HTML.
  • header('Content-Type: text/html; charset=utf-8') is already PHP's default, so the meta charset and the header agree.
    • Gotchas
  • The charset has to come early. The browser only looks for <meta charset> in the first 1024 bytes. Put it first in the <head>.
  • Escaping is for HTML, not for everything. htmlspecialchars() makes a value safe in HTML text and in a quoted attribute. It doesn't make a URL safe in an href: javascript: links are still links. Check URLs from outside before you use them.
  • A div with a click handler isn't a button. It can't be reached with the keyboard, and screen readers don't announce it. Use <button>.
  • Every image needs alt text. It's what a screen reader says, and what shows when the image doesn't load. A purely decorative image gets alt="".

    • The W3C's checker at validator.w3.org/nu takes a URL, a file or pasted source, and lists every unclosed tag and misplaced element the browser quietly fixed for you. Paste in your page's source once in a while. It takes a minute and catches the bugs that only show up in one browser.

    HTML says what everything is. How it looks is a different language, in a different file. Next: CSS.
