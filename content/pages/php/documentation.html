Documentation: php.net Phillip Harrington

phpinfo() tells you about the PHP you have. The manual tells you about PHP: every function, every setting, and every change from one version to the next. It's at php.net, it's free, and it's good. This course can't cover every function PHP has, and doesn't try. Learning to read the manual covers the rest.

What's the Manual?

The official PHP documentation, written and kept up by the people who make PHP. The parts you'll use most are the Language Reference (how PHP itself works: variables, operators, functions, classes) and the Function Reference (every built-in function, grouped by extension). There's also a Security section, worth reading once.

A Function's Page

Every function gets a page, and they're all laid out the same way:

  • The versions, at the top: "(PHP 4, PHP 5, PHP 7, PHP 8)" means it's been around forever. "(PHP 8)" means it's newer, and older servers won't have it.
  • Description: the signature, one line that says what goes in and what comes out.
  • Parameters: what each thing you pass it means.
  • Return Values: what you get back, and when. Read this one every time.
  • Changelog: what changed, and in which version. If code acts differently on two servers, look here.
  • Examples, then See Also, for its relatives.
  • User Contributed Notes, at the bottom: comments from readers, some of them twenty years old. Sometimes the best thing on the page, sometimes wrong. The manual above them is the one that counts.
    • In 1843, Ada Lovelace translated Luigi Menabrea's French article about Charles Babbage's Analytical Engine, and added notes of her own, longer than the article itself. Note G set out, step by step, how the engine could calculate Bernoulli numbers: the first published computer program. It came with documentation, because it was documentation. How It Works

    The fastest way to a function's page, and through it:

    1. Go to php.net/ and the function's name, like php.net/strpos. It sends you straight to the page.
    2. Read the signature (below).
    3. Read Return Values, and any warning box near it.
    4. Check the versions and the Changelog against the PHP you're running.
    5. Then the examples.
    Reading a Signature strpos(string $haystack, string $needle, int $offset = 0): int|false
  • strpos is the name. In the parentheses, the parameters, each with its type: two strings, then an int.
  • $offset = 0 has a default, so you can leave it off. Parameters without one are required.
  • After the colon is what comes back: int|false, an integer or false. The | means "or." Types get a lesson of their own soon, in Variables, Types and strict_types.

    • That int|false is the whole story of this function's most famous bug, and the manual warns about it in a box on the page: the position of something at the very start is 0, and 0 looks false.

    Try It

    PHP can show you a signature too, with no browser:

    docker run --rm php:8.4-cli php --rf strpos

    Only the new part:

    Show what PHP knows about the function strpos: its parameters and what it returns.

    It lists the parameters, marks the optional one with its default, and ends with Return [ int|false ]. Now see what happens to code that read the name and skipped the page. In a folder, make strpos.php:

    Run it:

    docker run --rm -v "$PWD":/app -w /app php:8.4-cli php strpos.php

    "apple" is right there at position 0, and the loose check says "no apple." The strict check, !== false, gets it right; Operators explains the difference. And str_contains(), new in PHP 8.0, answers the yes-or-no question without the trap. Its page says "(PHP 8)" at the top, which is how you'd know whether your server has it.

    In PHP
  • php --rf strpos: a function's signature, from PHP itself.
  • php --re mbstring: everything an extension provides.
  • function_exists('str_contains'): whether this PHP has a function, when code has to run on more than one version.
  • PHP_VERSION and php -v: which version's manual you should be reading.
    • Gotchas
  • Tutorials outlive the functions they teach. The old mysql_query() family is in thousands of tutorials, and it was removed in PHP 7.0. If the manual page says a function is removed or deprecated, the tutorial is old. php --rf mysql_connect says "does not exist."
  • The warning boxes are the point. The manual puts the traps in boxes marked Warning or Caution, like strpos's. They're there because people kept falling in.
  • The default can change between versions. The Changelog is where you find out a function behaves differently in PHP 8 than it did in 7. Check it before you blame your code.
  • The English manual is the most current. The translations are good, but they can lag behind.

    • Set up a custom search in your browser with the address https://www.php.net/%s and a keyword like php. Then typing php array_map in the address bar opens the page. Most browsers call these site search or keyword shortcuts, in their search settings.
