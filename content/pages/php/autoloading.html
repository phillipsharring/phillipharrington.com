Autoloading with Composer and PSR-4 Phillip Harrington

The last few lessons each started with a stack of require lines, one per class, in the right order. With five classes that's tidy enough. With five hundred, it's a job, and a missed line is a crash. Autoloading hands the job to PHP: when it meets a class it hasn't seen, it asks you where the file is. A naming rule answers, and Composer writes the code.

What's Autoloading?

A function you give PHP. The first time code uses a class PHP doesn't know yet, PHP calls that function with the class's name. The function works out which file holds the class and loads it. If it doesn't, PHP stops with Class "..." not found.

Namespaces

A namespace is a family name for classes, so yours don't collide with everyone else's. namespace App\Text; at the top of a file makes the class in it App\Text\Shout. Other files can write the full name, or say use App\Text\Shout; once at the top and then just Shout.

PSR-4

A rule for where a class's file is, from its name. Pick a prefix and a folder: App\ is src/. Then every backslash after the prefix is a folder, and the last part is the file name:

App\Greeter src/Greeter.php App\Text\Shout src/Text/Shout.php

One class per file, and the file named exactly like the class.

Composer

PHP's package manager, from Tools. It installs other people's code into a vendor folder, and writes one autoloader, vendor/autoload.php, for their classes and yours. Your project's settings go in composer.json.

By the late 2000s, every big PHP framework had its own way of naming and loading classes, so code from one rarely worked in another. In 2009, people from several of them formed the Framework Interoperability Group, PHP-FIG, to agree on a few things. Their first standard, PSR-0, was about exactly this: how a class name maps to a file. PSR-4 replaced it. Composer came out in 2012, built on those rules, and within a few years nearly every PHP project used it. How It Works
  1. composer install reads composer.json, downloads any packages it lists into vendor, and writes vendor/autoload.php.
  2. Your script requires that one file, first thing.
  3. It registers an autoloader with PHP, using spl_autoload_register().
  4. Your code says new Greeter(...). PHP doesn't know App\Greeter yet, so it asks the autoloader.
  5. The autoloader applies the PSR-4 rule, finds src/Greeter.php, and requires it. Then the code carries on as if the class had been there all along.

Classes load only when they're used. A page that never touches a class never reads its file.

The autoload part is the PSR-4 rule: App\ is src/ (with the backslash doubled, because it's JSON). Install, in Composer's own container:

docker run --rm -v "$PWD":/app -w /app composer:2 composer install

There's no package to download yet, so it just writes vendor/autoload.php and a composer.lock. Now hello.php, with a single require:

docker run --rm -v "$PWD":/app -w /app php:8.4-cli php hello.php

HELLO, ADA! and HELLO, ZOË!, with the ë intact, because Shout uses mb_strtoupper(); plain strtoupper() only knows ASCII letters, and Text and UTF-8 is why. Add a class to src and it just works, with no new require anywhere.

In PHP
  • namespace App\Text; first in the file (after declare(strict_types=1);), and use App\Text\Shout; to use a short name.
  • Shout::class is the full name as a string, 'App\Text\Shout', checked by your editor instead of typed by hand.
  • require __DIR__ . '/vendor/autoload.php'; once, at the top of every entry point: each page, each script.
  • spl_autoload_register() adds an autoloader of your own. You'll rarely need to.
  • composer dump-autoload rewrites the autoloader after you change the autoload part of composer.json.
  • composer require vendor/package adds a package, and Dependency Injection uses one.
    • Gotchas
  • Case counts, on the server. A Mac or Windows disk usually ignores case, so src/greeter.php loads App\Greeter fine on your laptop. The Linux server cares, and can't find it. Name files exactly like their classes.
  • Inside a namespace, PHP's own classes need a backslash. In namespace App;, new DateTimeImmutable() looks for App\DateTimeImmutable, and doesn't find it. Write new \DateTimeImmutable(), or use DateTimeImmutable; at the top.
  • vendor stays out of git. Commit composer.json and composer.lock, put vendor/ in .gitignore, and run composer install wherever the code goes. The lock file is what makes that install get the same versions you tested.
  • Packages are other people's code, running as yours. Anything you install can read your files and your secrets. Your Dependencies Are Your Code Too, in Security, has more.

    • The scripts part of composer.json gives a command a short name. The example has one: composer run hello runs php hello.php. Put your test, lint and setup commands there, and nobody has to remember the flags, including you in six months.

    When the autoloader can't find a class, PHP throws an Error, and so far that's always ended the program. It doesn't have to. Next: exceptions and try/catch.
