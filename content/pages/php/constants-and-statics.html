Constants, Static Variables and Functions Phillip Harrington

The bill splitter in the last lesson takes 1 to 50 people. Those numbers sit in the code bare, and the next person to read it has to guess what 50 means, or find every other 50 when the limit changes. A constant gives a value a name. Then there's the other thing PHP calls "static": values and methods that belong to a class, or a function, instead of to any one object. Constants are an easy yes. Statics need more care.

What's a Constant?

A name for a value that can't change while the program runs. By convention it's in capitals: MAX_PEOPLE. Three kinds:

  • const MAX_PEOPLE = 50; at the top of a file, or in a namespace.
  • define('APP_NAME', '...'), which works anywhere, even inside an if, and can build the name at run time.
  • A class constant, public const MIN_PEOPLE = 1; inside a class, used as Bill::MIN_PEOPLE. Most of your constants should be these: they live next to the code they're about.
    • What's Static?

    The word means two related things in PHP.

    A Static Variable

    A variable inside a function, declared with static, that keeps its value from one call to the next instead of starting over.

    Static Properties and Methods

    A property or method that belongs to the class, not to any object made from it. A static property has one value, shared by every object of that class. A static method is called on the class, Counter::everyone(), with no object, so it has no $this. Inside the class, self:: reaches them.

    How It Works
    1. A constant is set once. Try to set it again, and PHP warns you and keeps the first value.
    2. A static variable is set the first time its function runs, and kept after that.
    3. A static property is set when the class loads, and every object, and every other piece of code that can see it, shares the same one.
    4. All three last until the end of the request, and no longer. The next request starts PHP fresh.

    Step three is the catch. A static property is a global variable with a class name on it. Any code anywhere can depend on it, or change it, and nothing in a function's signature tells you that it does.

    Try It

    All of them in one file, statics.php:

    docker run --rm -v "$PWD":/app -w /app php:8.4-cli php statics.php

    The constants read like words. The tickets count 1, 2, 3, because the static variable remembered. And the counters: a counted 2, b counted 1, and the static count, shared by both, says 3.

    Now the trouble with a static method. why-not.php has two greetings, one that calls a static Clock::hour(), and one that's handed the hour:

    docker run --rm -v "$PWD":/app -w /app php:8.4-cli php why-not.php

    The welded one can only tell you what it says right now. To check its afternoon greeting, you wait until the afternoon, or change the computer's clock. The other one says what it says at 9 and at 15, today, in one run. Same logic. The difference is whether the code reaches out for what it needs, or is given it.

    Last, the end of the request. request.php has the same ticket counter as a web page:

    docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000

    Ask for http://localhost:8000/request.php as many times as you like: ticket 1, every time. Each request gets a fresh PHP, statics and all.

    When Not to Use Static

    Static methods are easy to call from anywhere, and that's the problem. A class that calls Clock::hour(), Db::query() or Mail::send() has a dependency you can't see from outside and can't swap out. To test it, you need the real clock, the real database, the real mail server. To change it, you hunt down every call.

    So in this course, and in code you'll be glad you wrote, the rule is: no static methods on your own classes. Give an object what it needs, through its constructor, and call methods on that. Dependency Injection is that whole idea.

    You'll still see statics everywhere. Plenty of libraries and frameworks use them, especially for "named constructors," like Money::fromCents(500), a static method that just makes an object. Read them, use them where a library gives you no choice, and don't write your own. Constants are fine. A static variable inside a small function, for something like caching a value you worked out once, is usually fine.

    In PHP
  • const and define() for constants; defined('NAME') asks whether one exists.
  • Bill::MIN_PEOPLE from outside a class; self::MIN_PEOPLE from inside.
  • Class constants can have a visibility, private const, and, since PHP 8.3, a type: public const int MIN_PEOPLE = 1;
  • static $number = 0; inside a function.
  • self:: means the class the code is written in; static:: means the class it was actually called on, which matters once children are involved.
  • PHP's own constants are worth knowing: PHP_EOL, PHP_INT_MAX, M_PI, __DIR__.
    • Gotchas
  • Statics don't remember visitors. They reset every request, so they're no place for a hit counter or a cart. That's what sessions and databases are for.
  • Except when they do. Some servers, like FrankenPHP's worker mode, RoadRunner and Swoole, keep PHP running between requests. There, a static set during one visitor's request is still there for the next visitor's.
  • Static state leaks between tests. Tests run one after another in the same PHP process. A static set in one test is still set in the next, and tests that pass alone fail together.
  • A constant is not a secret. const API_KEY = '...' puts the key in your code, and your code goes in git. Secrets Out of Code has the fix.
    • In 1897, the Indiana House of Representatives passed a bill, without a vote against it, that would have given pi a wrong value in state law. A mathematics professor from Purdue happened to be at the statehouse that day, and helped talk the Senate out of it. The Senate put the bill off indefinitely. Constants are constant, whatever the paperwork says.

    When you catch yourself typing a bare number, like 50, 900 or 3, stop and give it a class constant: private const MAX_LOGIN_ATTEMPTS = 10;. The name explains it, the next change is one line, and a search finds every use. Magic Numbers in Code has more.

    Typed class constants are one of the newer things in PHP, and there's a whole set of them worth knowing. Next: modern PHP.
