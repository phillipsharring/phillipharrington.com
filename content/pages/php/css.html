CSS Phillip Harrington

HTML says what each part of a page is. CSS, Cascading Style Sheets, says how it looks: colors, fonts, spacing, layout. It usually lives in its own file, a stylesheet, that the browser fetches and the server sends as it is. PHP's part is small: link to it properly, and make sure browsers get the new copy when it changes.

What's CSS?

A list of rules. Each one is a selector, then properties in braces:

.note { color: #555; margin-top: 1rem; }

The selector, .note, picks which elements the rule applies to. Each property, like color, gets a value and ends with a semicolon.

Selectors
  • p: every element of that type.
  • .note: every element with class="note".
  • #total: the one element with id="total".
  • .dark .note: a .note anywhere inside a .dark.
  • a:hover: a link while the pointer is over it.
    •  The Cascade

    When two rules set the same property on the same element, one has to win. The more specific selector wins: an id beats a class, and a class beats a plain element. .dark .note, two classes, beats .note, one. When they're equally specific, the one that comes later wins. And some properties, like color and font-family, are inherited: set them on body, and everything inside follows. That's the "cascading" in the name.

    The Box Model

    Every element is a box: the content, then padding around it, then a border, then margin outside that, keeping other boxes away. By default, width is the content alone, so padding and border make the box wider than you said. box-sizing: border-box makes width include them, and most stylesheets set it on everything.

    Early web pages had almost no way to set their own looks, and browser makers were adding presentation tags to HTML one at a time. In 1994, Håkon Wium Lie, working at CERN, proposed style sheets for the web instead, and Bert Bos joined him on what became CSS. The first version became a W3C recommendation in 1996. How It Works
    1. The HTML names a stylesheet in its head: <link rel="stylesheet" href="/style.css">.
    2. The browser asks for it: another request, answered from the document root with text/css.
    3. It matches every rule against the elements in the page.
    4. Where rules disagree, the cascade decides, and the browser draws the result.
    5. It keeps the file in its cache, so the next page doesn't ask again, sometimes for a long time.

    Step five is why a change to your stylesheet sometimes doesn't show. The browser is still using the copy it kept. The fix is to change the URL whenever the file changes: a new URL is a new file, as far as any cache knows.

    Start it:

    docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000 -t public

    Open http://localhost:8000 and switch between Light and Dark. The only thing that changes is the body's class, and the cascade does the rest. In the dark theme the note is lighter gray: .dark .note is more specific than .note, so it wins.

    View the source and find style.css?v= and a number. That's when the file last changed. Edit style.css, reload, and the number changes too, so the browser fetches the new copy. Then try to slip something in through the theme:

    curl 'http://localhost:8000/?theme=%22%3E%3Cscript%3E'

    The body's class is light. The theme goes into the page unescaped, so the code takes only a value from its own list, and anything else gets the default. Never trust input, even when it's only picking a color.

    In PHP
  • filemtime($path) is when a file last changed, as a number. In the stylesheet's URL, it's a version that updates itself.
  • in_array($value, $allowed, true) before any input goes into a class name, a style or a stylesheet.
  • PHP doesn't send the stylesheet. The web server does, from the document root, with the right content type, as in How PHP Actually Runs.
    • Gotchas
  • "It didn't change" is usually a cache. Before you debug a rule, reload without the cache (Ctrl+Shift+R, or Cmd+Shift+R on a Mac), or check the version in the URL.
  • Input in a style is still input. A color from a form, put in a style attribute, can close the attribute and add anything. Allow-list it, or check it against a strict pattern like # and six hex digits.
  • !important wins, and then you're stuck. It jumps the cascade, so the next fix needs another one. Make the selector more specific instead.
  • Styling ids makes rules hard to beat. An id is so specific that overriding it takes another id. Style with classes.

    • Right-click any element and choose Inspect. The developer tools list every rule that applies to it, in cascade order, with the losers crossed out. When something looks wrong, that list tells you why faster than reading the stylesheet.
