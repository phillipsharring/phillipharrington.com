Arrays Phillip Harrington

Strings and numbers are one value each. Most of what a web app handles comes in groups: the items in a cart, the fields of a form, the rows from a database. PHP has one type for all of it, the array, and it does double duty as a list and as a set of named values. You'll use it in nearly every file you write.

What's an Array?

An ordered collection of values, each stored under a key. The key is an int or a string. The value can be anything, another array included.

Lists

Give PHP values with no keys, and it numbers them from 0: $sizes = ['small', 'medium', 'large']; puts 'small' at $sizes[0]. $sizes[] = 'extra large'; adds one on the end, as number 3.

Named Keys

Or name the keys yourself, with =>: ['id' => 1001, 'email' => 'alice@example.com']. That's how one row of data looks in PHP, and how $_GET, $_POST and $_SERVER come to you. Other languages call this a map, a dictionary or a hash. In PHP it's the same array.

Arrays in Arrays

A value can be another array: an order with a list of items, $order['items'][0]. A list of rows from a database is a list of named-key arrays.

In 1982, Edsger Dijkstra wrote a short note called "Why numbering should start at zero." His argument: with ranges written as "from the first, up to but not including the last," starting at 0 makes a list of N items run from 0 up to N, and the length is just the difference. Most languages, PHP included, count from zero. How It Works

The things you do with arrays, in roughly the order you'll need them:

  1. Make one, with [], or get one from PHP: $_GET, explode(), a database query.
  2. Check what's there before you read it: isset(), array_key_exists(), or ?? with a default.
  3. Walk through it with foreach ($items as $item), or foreach ($order as $key => $value) for the keys too. It goes in the order the items were added.
  4. Make new arrays from it: array_filter() keeps the items that pass a test, array_map() changes each one.
  5. Sort it, or count it, or join it into a string.

Assigning an array to another variable, or passing it to a function, makes a copy. Change the copy, and the original stays as it was. (PHP is clever about this and only really copies when one of them changes.)

Try It

The everyday moves. In a folder, make arrays.php:

docker run --rm -v "$PWD":/app -w /app php:8.4-cli php arrays.php

A few to look at closely. isset() says the theme isn't there, because its value is null; array_key_exists() says it is. The key '7' turned into the int 7, and '07' stayed a string. array_filter() kept the original keys. And the plain sort put alice last, because capital letters come before lowercase ones in the byte order.

Now the array you didn't ask for. Make query.php, which shows what a query string turns into:

docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli php -S 0.0.0.0:8000

From a second terminal:

curl 'http://localhost:8000/query.php?tag=php' curl -g 'http://localhost:8000/query.php?tag[]=php&tag[]=web&size[shirt]=large'

Only the new part:

Turn off curl's own meaning for [] and {} in a URL (it uses them to ask for a range of URLs), so the brackets go out as typed.

The second request made $_GET['tag'] a list and $_GET['size'] a named-key array, just by putting brackets in the names. (-g tells curl to leave the brackets alone.) Any visitor can do that to any field. Never trust input: code that expects a string has to check it got one, as query.php does, and refuse the rest.

In PHP
  • count($array): how many.
  • isset($a['key']): there and not null. array_key_exists('key', $a): there at all.
  • in_array($value, $array, true): is it in the list? Always pass the true, as Operators explained.
  • array_filter(), array_map(): new arrays from old. array_values() renumbers a filtered list from 0.
  • array_keys(), array_merge(), array_slice(), array_column(): pull out, combine, cut, and pick one field from every row.
  • sort() and rsort() for lists, asort() and ksort() to keep keys, usort() with your own comparison.
  • implode() and explode(): arrays to strings and back.
    •  Gotchas
  • Any input can be an array. ?email[]=x turns $_GET['email'] into one, and the string function you call next throws a TypeError. Check with is_string(), or is_array() when you do want a list.
  • The sort functions sort in place. sort($names) changes $names and returns true. $sorted = sort($names); gives you true.
  • sort() throws the keys away. On a named-key array, use asort() or ksort().
  • Number-like keys become ints. '7' becomes 7, so a ZIP code like '02134' stays a string but '12345' doesn't. Usually harmless, until you compare keys with ===.
  • A filtered list has holes. array_filter() keeps the keys, so the result might be 0, 2 and 5. Wrap it in array_values() if you need 0, 1, 2.

    • array_column($rows, 'name', 'id') turns a list of database rows into [id => name], ready for a select menu. Pass null as the middle argument, array_column($rows, null, 'id'), and you get every whole row, keyed by its id, so finding one is $byId[42] instead of a loop.
