Modern PHP Phillip Harrington

A lot of what people say about PHP is about PHP 5, which stopped getting fixes years ago. PHP 7 and 8 added types, and then a run of features that make code shorter and harder to get wrong. This isn't every one of them. It's the six you'll use every week, and that you'll see in any PHP code written lately.

The Features Enums

A type with a fixed list of values. An order's status is pending, paid or shipped, and nothing else. Before enums, that was a string, and 'shiped' was a string too. A backed enum gives each case a value to store:

enum Status: string { case Pending = 'pending'; case Paid = 'paid'; }

Status::Paid->value is 'paid', and Status::tryFrom('paid') turns it back. Store the value in a VARCHAR column, and let the enum be the list of what's allowed. Enums can have methods and constants, like a class.

Readonly

A readonly property can be set once, from inside the class, and never again. A readonly class makes every property readonly. For a value that shouldn't change after it's made, like an order that's been placed, it saves writing the checks.

Constructor Promotion

Put public, private or readonly in front of a constructor parameter, and it's a property too, set from the argument. The declare-assign-assign dance from Classes and Objects becomes one line per property.

Match

Like switch, but it's an expression that returns a value, it compares with ===, it has no fall-through, so no break to forget, and if nothing matches, it throws instead of quietly doing nothing.

Named Arguments

new Order(id: 1042, status: $status, totalCents: 4_500). Each argument says which parameter it's for. You can skip optional ones, and nobody has to remember whether the price came before the quantity.

The Nullsafe Operator

$order->coupon?->code gives the coupon's code, or null if there's no coupon, instead of an error. Pair it with ?? for a default.

PHP went from 5.6 straight to 7.0, in 2015. PHP 6 was a real project: an effort, started in the mid-2000s, to build Unicode into the language from the bottom up. It turned out to be slow and very hard, and it was abandoned around 2010. Books had already been published about it, so the next version skipped the number to avoid any confusion. Which is why UTF-8 in PHP is still the mb_ functions, from Text and UTF-8. How It Works

The features arrive one release at a time, on a schedule:

  1. A new version of PHP comes out every year, usually in November.
  2. For its first two years, it gets bug fixes.
  3. For two more, it gets security fixes only.
  4. Then nothing. Running it after that means running known holes.

Enums and readonly properties came in PHP 8.1, readonly classes in 8.2; match, named arguments, constructor promotion and the nullsafe operator in 8.0. The course uses 8.4, so all of them work. A server on an older version would refuse the newer ones with a parse error, which is why composer.json says which PHP the code needs, like the "php": ">=8.4" in Autoloading.

Run it with a status:

docker run --rm -v "$PWD":/app -w /app php:8.4-cli php order.php paid

Two orders, labeled by match. The one without a coupon says none, through ?-> and ??. The status is saved as the plain string paid. And the last line is PHP refusing to change a readonly property: Cannot modify readonly property Order::$totalCents. Now a status that doesn't exist:

docker run --rm -v "$PWD":/app -w /app php:8.4-cli php order.php lost

Unknown status. The status came from the command line, and as Euclid wrote in the margin of the Elements, never trust input: tryFrom() is the allow list, built in. Anything that isn't a case comes back null.

In PHP
  • Status::tryFrom($input) for input: a case or null. Status::from() throws a ValueError instead, for values you stored yourself and expect to be good.
  • Status::cases() lists every case, for a select box or a check.
  • $status === Status::Paid compares enums; each case is a single object.
  • match (true) { $n < 0 => ..., $n === 0 => ..., default => ... } for ranges.
  • A few small ones worth knowing: str_contains(), str_starts_with(), str_ends_with(), and 1_000_000, underscores to make long numbers readable.
  • PHP 8.4 added property hooks and asymmetric visibility, public private(set). Useful, newer, and not in this course's examples yet.
    • Gotchas
  • Readonly is shallow. A readonly property holding an object can't be pointed at a different object, but the object it holds can still change inside.
  • Readonly means really once. No setting it again, not even from inside the class. To change a readonly object, make a new one with the new value.
  • Named arguments make names part of the deal. Once callers write totalCents:, renaming the parameter breaks them.
  • A match with no default throws on anything unlisted. That's usually what you want: add a case to the enum, and every match that forgot it fails loudly with an UnhandledMatchError, instead of quietly doing the wrong thing.
  • An enum isn't a database column type. Store ->value as a string, and turn it back with from(). Don't reach for MySQL's own ENUM column: changing its list means changing the table, while a VARCHAR and a PHP enum change with a deploy.

    • Put #[\SensitiveParameter] in front of any parameter that holds a password, a key or a token: function login(string $email, #[\SensitiveParameter] string $password). If an exception passes through that function, its stack trace shows Object(SensitiveParameterValue) where the password would have been, so it never lands in your logs. PHP 8.2 and up.
